# Quefa 多代理商分销开放平台

这是与旧 Quefa 项目完全分离的多代理商分销与充值开放平台。支持平台收款分销，以及授权后“代理自收款、采购余额扣供货价”两种模式。代理自行接入支付渠道，Quefa 不保存代理支付私钥。仅支持直接充值和 Quefa CDK；客户可使用 Quefa 托管页或代理自建兑换页，底层供应信息不对外返回。本地配置默认关闭真实交易；生产部署使用独立总开关和通道开关，不会因保存凭据自动产生交易。

## 当前包含

- 合作工作台 `/workspace`：账号登录、网页下单、工单与等级申请审批、公告、双钱包；详见 `docs/15-合作工作台与双钱包.md`。
- 自建兑换 API：同代理直充/CDK、持久化幂等与查询；外发说明见 `docs/16-代理商自建兑换页面开发指南.md`。
- 双收款模式，零售退款与采购退款区分。分账管理是内部收益核算，非支付渠道自动分账。
- 内部架构、对外接入、代理商手册、数据字典、状态机、财务分录、部署恢复和上线清单。
- OpenAPI 3.1 及 Node.js/PHP/Python HMAC-SHA256 签名示例。
- TypeScript/Fastify API：租户鉴权、Nonce 防重放、幂等、商品、订单分页、支付抽象、履约、退款、台账、结算、Webhook Outbox、审计。
- 可点击确认的模拟支付宝付款页，付款后由 Quefa 更新订单并产生 Webhook。
- 可选平台支付宝电脑网站支付（密钥/RSA2）：收银台跳转、通知验签、主动查单；仅允许白名单限额实单联调。
- 后台托管支付宝配置（PAYMENT_PROVIDER=managed）：支持草稿、密钥校验、启用/关闭、凭据加密及订单绑定配置版本；平台不再开放 USDT 新付款。操作与部署要求见 [后台支付配置](docs/20-payment-settings.md)。
- 实单联调后台：充值逐笔批准、派发前取消、CDK 停用与结果未知锁定。详见 `docs/14-支付宝电脑网站支付与受控实单联调.md`。
- Quefa 品牌充值页、`QF-` CDK 兑换页、充值状态轮询；供应商域名、订单号与原始卡密只存在于服务端。
- 可切换的模拟/真实充值适配器，覆盖直充预检下单、CDK 签发兑换、轮询和签名回调。
- Quefa 内部充值供应管理页：加密保存供应连接、测试鉴权、查询余额、同步 GPT 套餐，只维护 Plus、Pro 5x、Pro 20x、Pro 50x 四项 CDK 映射并查看脱敏对账数据。
- API/Worker 共享的 SQLite WAL 持久化运行时；订单、支付尝试、履约、退款、幂等、Outbox 和投递任务在重启后保留。当前单机与低订单量生产使用同一持久化文件和一致性备份，扩容为多应用节点前迁移 PostgreSQL。
- 带 HMAC 签名、租约、退避与死信状态的真实 Webhook POST Worker。
- 可直接运行的代理商商城前端、服务端签名代理和 Webhook 接收示例。
- PostgreSQL 生产目标迁移与 RLS 策略，以及安全、跨租户、持久化和完整链路测试。
- 提交前持久化、未知结果只查询、跨进程任务占用、终态保护，以及支付/履约/CDK 与下游事件的事务一致性；最新复核结果见 `docs/13-项目复核与完善报告.md`。

## 本地验证

API 默认开放：代理商无需申请或预存即可创建服务端密钥并签名调用。采购余额为零时强制使用平台收款，不允许代理自收款/余额采购；管理员仍可停用异常账号，停用后返回 403。隔离模拟库可做专用测试记账，真实资金须实际核实到账。

```powershell
Copy-Item .env.example .env
npm install
npm run check
npm run build
```

启动联调环境可使用 `docker compose up --build`；另开终端执行 `npm run demo:partner`，然后打开 `http://127.0.0.1:3300`。详细步骤见 `docs/10-代理商沙箱联调指南.md`。

`src/infra/sqlite-repository.ts` 支持当前单服务器低并发生产，API 与 Worker 共享持久化数据。`NODE_ENV=production` 与 `EXECUTION_MODE=production` 已具备严格启动校验；支付宝和生产上游仍须在工作台分别保存、验证和启用。扩展为多节点、自动退款或更高财务并发前，应完成 PostgreSQL 仓储迁移、异机加密备份、KMS、渠道对账与固定出口网络。

## 安全提醒

模拟沙箱禁止放入正式凭据或真实 Session。生产环境使用独立数据库文件、受限文件权限、MFA 管理域名和关闭的沙箱路由。后台管理模式的支付宝私钥使用 AES-256-GCM 加密保存，主密钥留在部署秘密配置中，不从后台返回；供应秘密和待提交充值资料同样加密。新交易仅支持支付宝，不开放 USDT/DujiaoPay。SQLite 数据文件与备份仍包含敏感业务数据，必须限制访问并配置异机加密备份。正式扩流前仍须完成 `docs/08-上线检查表.md`。

充值供应管理的范围、配置顺序与生产安全要求见 `docs/12-Quefa充值供应管理后台.md`。平台管理接口必须置于内网/VPN 和受控管理域名后，不能作为代理商开放接口发布。
