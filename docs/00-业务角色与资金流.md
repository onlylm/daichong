# Quefa 多代理商分销模式：业务角色与资金流

版本：v0.3（2026-09-26）。最新用户决定已扩展双模式，具体以第 15、16 份文档及本段为准；下文“单平台收款”适用于 platform_collect，不再限制所有代理。

当前支持：平台收款分销，以及授权代理自行接支付、使用采购余额支付供货价。两种模式均由 Quefa 服务端履约。代理可网页登录下单或调用 API，可申请等级，由管理员审核调整；也可授权自建兑换页，供应信息不对外返回。账号角色、等级、商品价格、支付模式分别配置。

## 一句话定位

多个代理商负责推广和销售，Quefa 统一供货、统一用自己的支付宝收款、统一履约、统一退款，再把代理商应得的销售差价结算给代理商。

这里技术上仍使用 `merchant_id` 表示租户，但业务含义是“代理商/分销渠道”，不是支付宝收款商户。

## 角色边界

| 角色 | 负责 | 不负责/不可接触 |
|---|---|---|
| 买家 | 在代理商页面选购、扫描付款码、确认 Session 邮箱、查看结果 | 不知道 Quefa 上游，不接触 CDK |
| 代理商 | 推广、商城页面、选择授权商品、设置终端售价、调用 Quefa 接口、展示二维码/状态、提交退款申请、核对差价结算 | 不提供支付宝账号，不配置支付应用，不持有支付宝私钥，不直接退款，不接触上游密钥/成本 |
| Quefa | 给代理商供货价、生成自己支付宝的收款二维码、确认到账、加密处理 Session、调用上游、退款审核与原路退款、对账和结算 | 不把上游、支付密钥和内部真实成本暴露给代理商 |
| 上游 | 向 Quefa 提供实际商品/履约能力 | 对代理商和买家完全隐藏 |

## 业务链路

```text
买家进入代理商商城
  → 代理商按自己的终端售价调用 Quefa 开单
  → Quefa 用自己的支付宝应用生成收款二维码
  → 代理商页面展示二维码，买家付款到 Quefa
  → 支付宝只回调 Quefa，Quefa主动查单确认到账
  → 代理商页面收集并确认买家 Session，调用 Quefa 履约接口
  → Quefa调用隐藏上游完成履约
  → 代理商通过查单/Webhook展示成功或失败
  → Quefa按订单销售差价与代理商结算
```

买家全程留在代理商页面；代理商可以看到自己的订单和结果，但不看到 Quefa 支付配置或上游信息。

## 资金口径

```text
买家付款金额 = 代理商设置的终端售价
Quefa实际收款 = Quefa自有支付宝确认的实际到账金额
代理商销售差价 = Quefa实际收款 - Quefa对该代理商的供货价 - 补差退款
代理商待结算 = 尚未结算的代理商销售差价及后续调整
Quefa毛利 = Quefa供货价 - 上游真实成本 - Quefa承担的手续费/成本
```

示例：Quefa 给代理商供货价 110 元，代理商卖 135 元。买家向 Quefa 支付 135 元，代理商应得 25 元。若 Quefa 后续向买家补差退款 10 元，代理商应得变为 15 元。若 25 元已结算，旧结算单不变，下一期生成 `-10 元` 调整。

普通退款的损失承担方式必须按代理商合同规则版本化；无论如何，实际退款都由 Quefa 使用自己的支付宝执行，代理商只提交申请和查看结果。

## 支付配置唯一归属

系统只有 Quefa 平台级支付配置。代理商租户表、代理商应用和开放 API 中不得出现以下能力：

- 上传/配置支付宝私钥、公钥、应用证书或商户号；
- 选择自己的收款账户；
- 直接调用支付宝退款；
- 查看其他代理商或 Quefa 全局支付流水；
- 获取支付通道密钥、上游密钥或真实成本。

代理商的 `partner_id/app_id/key_id/client_secret` 只用于调用 Quefa 开放 API，与支付宝凭证没有关系。
