# 数据字典

版本：v0.2。数据库金额统一为 `bigint` 分，时间统一为 `timestamptz`，主键建议 UUIDv7。所有租户业务表必须含 `merchant_id`，软删除只用于可配置对象，交易事实不可删除。本文中的 `merchant` 是历史技术命名，业务含义统一为代理商/销售渠道，不是支付宝收款商户。

## 核心身份与租户

| 表 | 关键字段 | 说明 |
|---|---|---|
| `merchants` | `id, partner_id, name, status, settlement_cycle, timezone` | 代理商租户；`partner_id` 全局唯一，不代表支付宝商户号 |
| `merchant_users` | `merchant_id, user_id, role_id, status` | 代理商用户关系；一人可属于多个代理商 |
| `roles/permissions/role_permissions` | `code, scope` | 代理商与 Quefa 平台角色分域 |
| `partner_apps` | `id, merchant_id, app_id, name, status, allowed_ips` | 代理商商城/服务端调用应用；只用于 Quefa API 鉴权，不含支付配置 |
| `api_keys` | `merchant_id, app_id, key_id, secret_ciphertext, key_version, status, not_before, expires_at, last_used_at` | 密钥仅创建时返回；库中不存可直接读取的明文 |
| `nonce_records` | Redis key | `nonce:{partner}:{key}:{nonce}`，TTL 600 秒；数据库可选保留安全审计摘要 |

## Quefa 平台级支付配置

| 表 | 关键字段 | 说明 |
|---|---|---|
| `platform_payment_configs` | `id, provider, config_ciphertext, config_iv, config_auth_tag, key_version, status` | Quefa 自有支付宝等支付渠道配置；平台内部专用，不含 `merchant_id`，不开放给代理商角色/API |

同一环境、同一支付渠道只允许一个生效配置。配置由 Quefa 运维通过 Secret Manager/KMS 注入并轮换；数据库仅保存密文和密钥版本。代理商不能创建、查询、更新或选择此配置。

## Quefa 平台级充值供应配置

| 表 | 关键字段 | 说明 |
|---|---|---|
| `platform_supplier_connections` | `id, provider, environment, open_api_base, cdk_base, enabled, secret_ciphertext, key_version, config_version, last_test_status` | 平台内部充值供应连接；API Key、回调密钥和直充内部资源引用合并加密保存，不回显 |
| `supplier_plan_snapshots` | `connection_id, product, plan, acc_plan_key, enabled, purchasable, service_fee_usd_minor, pricing_version, synced_at` | GPT 套餐同步快照，只保存可售与价格信息 |
| `supplier_product_mappings` | `product_code, connection_id, fulfillment_mode, supplier_product, supplier_plan, enabled, version` | Plus、Pro 5x、Pro 20x、Pro 50x 四项 GPT CDK 套餐的内部映射；生产默认停用 |

这三张表是平台资源，没有 `merchant_id`，不进入代理商 RLS 会话，并且对 `PUBLIC` 撤销全部权限。供应连接只服务充值履约，不建立任何虚拟支付工具管理模型，也不向代理商暴露。

`0005_recharge_recovery.sql` 为履约增加租约令牌、CDK 查询令牌的 IV/认证标签/密钥版本和清理时间，为 CDK 签发增加任务令牌，并增加“一笔订单最多一个进行中或成功履约”的唯一约束。SQLite 沙箱把同类字段保存在记录载荷中；查询令牌使用独立 AAD 加密，终态清除。

## 商品与定价

| 表 | 关键字段 | 说明 |
|---|---|---|
| `products` | `id, product_code, name, category, fulfillment_mode, status, currency, max_quantity` | 平台商品主数据；当前四项新商品均为 `cdk`，`direct` 仅保留历史订单兼容 |
| `merchant_product_grants` | `merchant_id, product_id, status, valid_from, valid_to` | 代理商商品授权 |
| `merchant_price_rules` | `merchant_id, product_id, supply_price_minor, max_sale_price_minor, version, valid_from, valid_to` | 供货价/销售上限；订单保存快照 |
| `upstream_product_mappings` | `product_id, provider, upstream_sku, encrypted_config` | 仅内部可见 |

## 订单、支付与履约

| 表 | 关键字段 | 说明 |
|---|---|---|
| `orders` | `id, merchant_id, merchant_order_no, product_id, quantity, sale_amount_minor, supply_amount_minor, currency, payment_status, fulfillment_mode, expires_at` | `(merchant_id, merchant_order_no)` 唯一；保存履约模式快照 |
| `order_metadata` | `order_id, merchant_id, metadata jsonb` | 只允许非敏感代理商业务标识，限制大小和层级 |
| `payment_attempts` | `id, merchant_id, order_id, payment_config_id, provider, status, provider_trade_no, requested_minor, received_minor, fee_minor, qr_payload, expires_at` | 订单归属代理商，但支付尝试引用 Quefa 平台级配置；外部流水号在 provider 维度唯一 |
| `fulfillment_attempts` | `id, merchant_id, order_id, attempt_no, fulfillment_mode, voucher_id, status, failure_code, worker_state, lease_until, next_check_at, supplier_order_ref_ciphertext` | `(merchant_id, order_id, attempt_no)` 唯一；供应引用仅内部加密保存 |
| `cdk_vouchers` | `id, merchant_id, order_id, public_code, plan, status, issue_attempts, next_attempt_at, supplier_cdk_id_ciphertext, key_version, consumed_at` | 对外只交付唯一代理品牌公开号；签发失败退避重试；底层码放入 `sensitive_payloads`，成功后清除 |
| `sensitive_payloads` | `merchant_id, owner_type, owner_id, ciphertext, iv, auth_tag, wrapped_dek, key_version, cleared_at` | Session/临时凭证；AAD 绑定租户与对象 |
| `platform_supplier_webhook_events` | `event_id, event_type, client_request_id, payload_hash, received_at, processed_at` | 平台内部供应回调幂等表；不授予代理商访问 |
| `state_transitions` | `merchant_id, aggregate_type, aggregate_id, from_state, to_state, reason, actor_type, actor_id, request_id` | 追加写审计轨迹 |

## 字段与约束规范

- `merchant_id` 不接受来自请求体，由鉴权上下文注入。
- `platform_payment_configs` 是明确的平台级例外：不得添加 `merchant_id`，不得通过代理商 API/RLS 会话访问。
- `platform_supplier_connections`、`supplier_plan_snapshots`、`supplier_product_mappings` 也是平台级例外，只能由 Quefa 内部后台角色访问。
- `partner_apps.app_id` 与支付宝 `app_id` 完全无关；命名相似时必须在界面和日志中标注“开放 API 应用”。
- 对外 ID 使用不可枚举 ID；数据库内部序列不得直接对外。
- `*_minor >= 0`，只有分录方向决定正负；结算 `payable_minor` 可因冲正为负。
- `currency` 当前检查为 `CNY`，未来按同币种分录平衡，禁止跨币种直接相减。
- `metadata` 最大 4 KiB，禁止键名匹配 `token/session/cookie/password/secret/authorization`。
- `created_at` 不变，`updated_at` 由数据库触发器或仓储统一维护。
- 交易表外键优先包含 `(merchant_id, id)`，防止错误关联到另一租户。

## RLS 模式

生产连接分为迁移角色、平台后台角色、租户 API 角色。租户 API 角色没有 `BYPASSRLS`，每个事务设置：

```sql
SELECT set_config('app.merchant_id', $1, true);
```

策略使用 `merchant_id = current_setting('app.merchant_id', true)::uuid`。连接归还池前必须结束事务；禁止使用会泄漏会话变量的非事务设置。
