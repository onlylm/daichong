# 代理 API 总览与资格聚合

## 问题

平台打开代理 API 总览时，旧实现会对每个启用代理分别读取 API 状态、全部历史申请工单、采购钱包流水、应用和 Webhook，形成随代理数量线性增长的 N+1 查询。代理等级资格中的累计充值额也会读取并解码该代理全部充值历史。

系统已改为“API 默认开放、无需申请或预存”，但旧的预存申请校验私有函数仍留在服务中，容易让后续维护误以为 API 仍受 ¥110 预存门槛控制。

## 本次改造

- SQLite 用单条聚合查询返回全部启用代理的 API 开关、配置版本、采购余额、应用数量、启用 Webhook 数量和是否存在历史待审申请。
- 单代理 API 摘要的采购余额使用钱包聚合；历史 API 申请按代理和字段条件查询，不再读取该代理全部工单。
- 已核验充值凭证使用状态、金额、到账凭证和对应钱包入账记录精确查询。
- 等级资格中的累计已到账充值额使用数据库 `SUM`。
- 每日核算单人工确认打款前的收益余额使用钱包聚合。
- 删除已经无调用方的旧“API 申请时必须预存 ¥110”判断函数；API 默认开放及管理员人工停用规则不变。

## 验证

SQLite 集成测试创建真实已核验充值，确认：

- API 总览返回正确开通状态和采购余额，且未调用逐代理全量读取；
- 单代理摘要识别已核验充值并返回正确余额；
- 等级资格累计充值额正确；
- 上述路径未回退到 `listOperations` 全量读取。

本地分支尚未部署生产。历史 API 申请只用于兼容查看，新代理无需申请或预存；无预存余额时仍强制使用平台收款。
