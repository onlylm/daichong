# 财务分录规则

版本：v0.2。本文定义“Quefa 集中收款、代理商推广销售”的业务口径；正式上线前需由财务与会计师确认科目命名、税务和合同归属。本文数据库字段中的 `merchant` 均指代理商租户。

## 1. 基本原则

- 交易事实只追加，不直接修改历史分录；更正使用等额反向分录并关联原交易。
- 金额为整数分，借贷平衡，同一分录组币种一致。
- “支付状态”“履约状态”“退款状态”“结算状态”独立，财务由事件驱动。
- 订单保存供货价、销售价和费率快照；后续改价不影响历史订单。
- 上游真实成本和 Quefa 毛利仅平台财务可见。
- 买家全款进入 Quefa 自有支付宝；代理商不收款、不查支付宝流水，也不执行支付宝退款。
- Quefa 与代理商只按本平台订单、退款和结算分录对账，不要求代理商核对 Quefa 的支付宝总流水。

## 2. 分析科目

| 科目代码 | 含义 | 代理商可见 |
|---|---|---|
| `payment_channel_receivable` | 支付渠道应收/清算中 | 否 |
| `cash_at_channel` | Quefa 渠道实际收款 | 仅显示本代理商订单金额，不显示渠道凭证/总流水 |
| `agent_sale_amount` | 买家向 Quefa 支付的代理商成交金额 | 是 |
| `quefa_supply_revenue` | Quefa 对代理商供货价 | 是 |
| `agent_margin_payable` | Quefa 应付代理商的销售差价/待结算 | 是 |
| `customer_refund_payable` | 已批准待退用户金额 | 是 |
| `payment_fee_expense` | 支付手续费 | 否 |
| `upstream_cost_expense` | 上游真实成本 | 否 |
| `quefa_gross_profit` | Quefa 毛利分析投影 | 否 |
| `agent_settlement_clearing` | Quefa 向代理商已结算划转/应付清算 | 是 |

实际总账科目可与此不同，现有代码中的 `merchant_*` 科目可在数据库兼容期保留，但业务展示统一称“代理商”。业务子账必须能单独还原：买家付款、Quefa 支付渠道实收、Quefa 供货价、普通退款、补差退款、代理商差价、待结算、手续费、上游成本和 Quefa 毛利。

## 3. 业务事件

### 支付成功

订单终端成交价/应付金额 `P`，Quefa 支付渠道实际确认到账 `R`，Quefa 供货价 `S`，手续费 `F`：

```text
记录买家应付 P
记录 Quefa 支付渠道实收 R
代理商销售差价初始 = R - S
代理商待结算增加 = R - S
Quefa 供货收入 = S
支付手续费 = F
```

`P` 与 `R` 正常应相等；不一致必须形成对账差异，不能静默用其中一个覆盖另一个，也不能在差异关闭前进入代理商结算。

### 履约成本确认

上游真实成本 `C` 确认时记录内部成本。Quefa 毛利分析值：

```text
Quefa毛利 = S - C - F - Quefa承担的退款/其他直接成本
```

代理商看不到 `C` 与 Quefa 毛利。

### 普通退款

退款 `N` 成功时减少 Quefa 渠道资金/形成渠道退款，减少买家净付款；依据合同将退款在代理商差价、Quefa 供货收入和相关费用间拆分。拆分规则必须在商品/代理商合同策略中版本化，不能硬编码为单一比例。代理商只提交退款申请，退款出款和渠道结果确认均由 Quefa 完成。

### 补差退款

补差 `D` 由代理商销售差价承担：

```text
代理商销售差价 = R - S - D
代理商待结算减少 D
```

若待结算已进入未封存结算草稿，重新生成草稿；若结算已封存/已付，生成下一期负向调整 `-D`，旧结算单不变。

## 4. 指定示例

代理商终端售价 135.00，买家向 Quefa 支付 135.00，Quefa 自有支付宝确认实收 135.00，Quefa 供货价 110.00，暂不考虑手续费与上游成本：

| 时点 | 买家净付款/Quefa实收 | 供货价 | 补差 | 代理商销售差价/待结算 |
|---|---:|---:|---:|---:|
| 支付后 | 135.00 | 110.00 | 0.00 | 25.00 |
| 补差退款 10.00 后 | 125.00 | 110.00 | 10.00 | 15.00 |

若 25.00 已在 S1 结算并打款，S1 仍显示 25.00；S2 出现 `-10.00`，关联退款与 S1 原结算行，净待支付减少 10.00。

## 5. 结算生成

结算候选只取已达到合同可结算条件且未被其他结算行占用的分录。使用数据库唯一约束防止一条待结算分录进入两张结算单。生成时保存来源分录、订单号、金额、周期与规则版本；财务确认后 `sealed_at` 非空且触发器禁止 UPDATE/DELETE 明细。

付款确认必须记录银行/支付流水、付款时间、操作者与附件摘要。付款失败不修改结算金额，仅改变付款状态并创建新付款尝试。

## 6. 对账

Quefa 内部每日导入自有支付宝账单并按渠道流水号、订单号、金额匹配：本地有/渠道无、渠道有/本地无、金额不符、状态不符、手续费不符。该渠道账单不向代理商开放；代理商只核对自己在 Quefa 平台的订单、退款和结算。差异不得通过直接改金额消除；修复动作需产生支付确认、冲正、补记或人工说明。

上游成本账单按上游订单摘要匹配，原始敏感标识仅内部可见。对账批次保存来源文件 SHA-256、行数、总额、导入人和完成时间。

## 7. 不变量

- 每个 `ledger_transaction` 借方合计等于贷方合计。
- 可退款金额不得小于 0；累计成功退款不得超过渠道可退金额。
- 代理商待结算余额可因结算后冲正为负，但必须显式展示并有来源。
- 已封存结算明细不可变；调整必须在新结算期。
- 可由不可变分录重算所有余额，投影与重算结果不一致即告警。
