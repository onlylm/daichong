# SQLite 开票持久化验收

更新时间：2026-10-01

## 业务口径

- 开票申请必须关联一笔已付款、未全额退款的正式订单；1 元支付联调订单不能开票。
- 仅受理企业抬头，公司名称、纳税人识别号、收票邮箱和联系人必填。
- 发票类目固定为“技术服务费”。
- 发票面额是代理商客户需要开具的金额，不等同于 Quefa 订单供货价或平台收款金额。
- 代理商按发票面额另付 5% 补差价；该支付使用独立支付单，支付宝主题固定为“订单补差价”，不进入订单销售额、代理佣金或每日核算。
- 只有支付宝验签通知或主动查询确认足额到账后，申请才从“待支付”进入“已提交”。平台管理员随后人工开始处理并登记开票完成，不自动开票、不自动打款，也不要求多人复核。

## 自动化验收

`tests/sqlite-invoice-end-to-end.test.ts` 使用隔离 SQLite 文件依次验证：

1. 代理订单付款后提交 ¥1000 发票申请，系统计算独立补差价 ¥50。
2. 支付宝预下单参数中的金额为 ¥50，主题为“订单补差价”。
3. 进程关闭前申请仍为待支付；数据库文件不包含明文税号。
4. 重启后接收验签成功通知，重复通知只确认一次，申请进入已提交。
5. 其他代理不能读取该申请；已付款申请不能再次生成支付单。
6. 再次重启后，平台管理员人工开始处理并登记发票号码。
7. 第四次重启后，代理仍可看到已开票终态，补差价支付记录与审计记录完整。
8. 平台处理审计归属于申请所属代理商，同时保留平台管理员操作人；不会成为无法在代理详情追溯的全局孤立记录。

## 安全与验证边界

税号使用现有敏感字段加密机制落盘，仅有对应代理商和有权限的平台人员可通过服务层读取。测试使用假的支付宝客户端与临时数据库，不请求支付宝、不产生真实付款、不访问生产数据。

```powershell
npm test -- --run tests/sqlite-invoice-end-to-end.test.ts tests/invoice-applications.test.ts
```

该验收不替代生产支付宝配置验证、真实回调网络检查、管理员浏览器验收或正式发票业务抽样。
