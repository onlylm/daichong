# 支付宝电脑网站支付与受控实单联调

新增后台管理模式见 [后台支付配置](20-payment-settings.md)：将 PAYMENT_PROVIDER 设置为 managed 后，可在工作台分别配置、启停支付宝与 USDT。本文的 alipay_page 文件模式仍兼容；已有旧订单迁移时须保留旧密钥。两种模式都保留本页的白名单、金额上限和充值逐笔审批。

## 交付范围

- 平台自有支付宝「电脑网站支付」，密钥/RSA2 模式。使用官方 SDK 的 `alipay.trade.page.pay`；不是当面付。
- 已实现通知验签、应用/收款 PID/金额/订单/交易号校验、幂等入账、主动查单补偿。浏览器返回参数不作为到账依据。
- 代理商只对接 Quefa。`qr_payload` 在此模式下是 Quefa 付款页链接，应显示为“前往付款”按钮，不能当成当面付二维码内容。
- 已实现 CDK 停用、停用超时锁定与再次核对、充值逐笔批准与派发前取消。对外只展示 Quefa 订单和兑换码。
- 默认保持模拟模式。本地测试未使用真实凭证，不能证明生产链路已验收。
- 当前用于指定代理的有限实单联调，不是全面生产上线：`NODE_ENV=production` 仍拒绝启动，PostgreSQL 仓储与人员登录/MFA 尚待交付。

## 配置准备

支付宝应用须已上线并开通电脑网站支付，实际权限以商户后台为准。需要：

1. APPID。
2. 收款商户 PID（`seller_id`，不是手机号）。
3. 应用私钥文件，PKCS8 或 PKCS1，与 `ALIPAY_KEY_TYPE` 一致。
4. 支付宝公钥文件，**不是应用公钥**。
5. Quefa HTTPS 域名；异步通知路径为 `/internal/webhooks/alipay`，必须公网可达、不重定向、不要求登录。其他后台路径应由 VPN/IP 白名单保护。

私钥只保存在服务器受限目录或密钥系统，不发送给代理商，不粘贴到聊天、截图或日志。仓库忽略 `secrets/` 与 `*.pem`。密钥文件只授予服务账号读取权限；禁止开启支付宝 SDK 调试日志。

在独立联调部署中配置（占位内容必须替换）：

```dotenv
NODE_ENV=development
ENABLE_SANDBOX_ROUTES=false
STORAGE_DRIVER=sqlite
SQLITE_PATH=./data/quefa-live-test.sqlite
PUBLIC_BASE_URL=https://你的Quefa域名
PAYMENT_PROVIDER=alipay_page
ALIPAY_APP_ID=你的APPID
ALIPAY_SELLER_ID=你的收款PID
ALIPAY_PRIVATE_KEY_PATH=./secrets/alipay-app-private.pem
ALIPAY_PUBLIC_KEY_PATH=./secrets/alipay-public.pem
ALIPAY_KEY_TYPE=PKCS8
LIVE_TEST_ENABLED=true
LIVE_TEST_PARTNER_IDS=pt_live_test
LIVE_TEST_MAX_ORDER_MINOR=16000
LIVE_TEST_MAX_TOTAL_MINOR=32000
LIVE_TEST_MAX_ORDERS=2
DEMO_PARTNER_ID=pt_live_test
DEMO_KEY_ID=key_live_test_01
# 必须使用各自独立的随机值替换默认 DEMO_CLIENT_SECRET、
# PLATFORM_ADMIN_TOKEN、PORTAL_TOKEN_SECRET 和 DATA_ENCRYPTION_KEY。
FULFILLMENT_PROVIDER=zovocard
ZOVOCARD_CDK_FUNDING_CAP_MINOR=2500
```

金额示例不是价格承诺：人民币分限额分别是 ¥160/笔、累计 ¥320，最多 2 笔；CDK 上限示例 `2500` 按上游 USD minor 口径表示 $25，应按实际套餐与注资报价确认，可能不足以兑换某些套餐。上游 API Key 还应设置消费上限和服务器 IP 白名单。**Quefa 的人民币订单限额不等于上游实际美元支出限额。**

必须使用专用数据库，不要混入模拟数据；API 与 Worker 使用相同配置、密钥和数据库绝对路径。禁止删除数据库来清空预算。所有未支付、关闭和退款的联调订单也占用总笔数/金额；正常重启不会重置。

原商品授权有最低供货价，不能直接下 ¥0.01 订单。若只测试小额收款，必须由平台明确配置独立测试商品价格，并保持模拟履约；不要把低价支付测试单映射到真实高价充值套餐。

## 联调顺序

Docker 使用独立的 `compose.live-test.yaml`，不与模拟沙箱的 `compose.yaml` 合并；配置保存为 `.env.live-test`，密钥放在 `secrets/` 并授予容器服务账号读取权限。运行 `docker compose -p quefa-live-test -f compose.live-test.yaml up --build -d`，HTTPS 反向代理转发到 `127.0.0.1:3201`。两个容器共享专用数据库卷；不要用带删除卷的命令清理此环境。该部署文件尚未在目标服务器执行验收。

1. 在 `/internal/admin/supply` 配置生产充值供应连接、API Key、回调秘密；只读测试余额、同步套餐、核对商品映射。不开通支付卡管理。
2. 确认支付宝应用权限与收款 PID，启动 API 和 Worker；白名单代理先读商品再下单。
3. 客户打开 `qr_payload`，点击“前往支付宝付款”，自行确认真实支付。返回 Quefa 等待服务端确认；可点“我已付款，核对结果”，Worker 也会主动查单。
4. CDK 订单付款后自动发上游码并加密保存，对外仅给代理品牌公开号。**发码本身就可能扣服务费。**
5. 客户通过直充或 CDK 入口提交资料。联调订单停在 `queued`，显示等待确认、尚未派发。
6. 打开 `/internal/admin/live-tests`，输入平台管理令牌：
   - 仅验证 Quefa 接收到资料：取消尚未派发任务，再停用未兑换 CDK。这不证明上游接受了充值。
   - 验证上游真实受理：逐笔“批准真实充值”。上游可能立即扣费执行，不能保证仅受理、无扣费或可撤销。
7. 已派发任务只查结果，不重复提交。响应丢失进入结果确认流程。平台再通过订单查询与 Webhook 给代理商状态。
8. 核对支付宝实收、上游服务费/订阅资金和通知后，再决定扩大额度或范围。

## 平台内部接口

均要求 `X-Platform-Admin-Token`，不提供给代理商：

| 方法与路径 | 请求体及用途 |
| --- | --- |
| `GET /internal/admin/api/supply/test-orders` | 列出实单测试订单和本地状态，无上游秘密 |
| `POST /internal/admin/api/supply/test-orders/{orderId}/disable-cdk` | `{"confirm_disable":true}`；停用未兑换码 |
| `POST /internal/admin/api/supply/test-orders/{orderId}/fulfillments/{fulfillmentId}/approve` | `{"acknowledge_real_charge":true}`；批准真实提交 |
| `POST /internal/admin/api/supply/test-orders/{orderId}/fulfillments/{fulfillmentId}/cancel` | `{"confirm_cancel":true}`；仅取消尚未派发任务 |

停码失败/超时保持 `disabling`，不可兑换、不可普通退款；重试停码接口进行确认，不把超时当成功。确认后 `disabled`，发送 `cdk.disabled` 事件。

## 取消与退款的区别

- 本地任务取消：仅证明该任务尚未派发。
- 上游 CDK 停用：使用文档明确的 `/gpt-direct/cdks/{id}/disable`，不代表退服务费。
- 上游网页“删除并退款”：文档描述符合条件的未用购买码可操作；主 OpenAPI 未给出退款端点，本次未虚构该 API。需网页确认并对账。
- 支付宝退款：本次未接真实退款 API。需退测试付款时，先确认充值未派发、CDK 已停用，再在支付宝商户端处理并保存流水。**平台不自动同步这种后台手工退款，不能据平台 `paid` 判断实际剩余实收。**
- 现有模拟退款入口拒绝支付宝订单。渠道手续费当前未自动取得，不能把账内默认 0 当成真实费率。

## 验证依据

参考 [支付宝官方 Node.js SDK](https://github.com/alipay/alipay-sdk-nodejs-all) 的网站支付、通知验签和 v2 查询接口；上游停码语义依据提供的 `spacexcard-openapi.md` 6.18.6 与 CDK 文档。商户当前权限是否接受这些调用，仍需部署后实测。

自动化涵盖 RSA2 签名/篡改、错误应用与 PID、金额不符、重复通知与字段、浏览器假跳转、查单补偿、预算并发/重启、模拟订单隔离、逐笔批准、派发前取消及停码恢复。测试不访问真实资金接口。
