# 人工完成与新佣金入账的收款凭证一致性

日期：2026-10-02。仅开发分支与隔离测试环境验证，未部署生产。

订单显示“已支付”不足以单独证明收款。登记人工完成前，服务端还会核对同一订单的支付尝试：状态为已支付、到账金额正确、渠道流水与订单一致，并有实际付款时间。平台收款以客户订单金额核对；代理自收款采购以供货金额核对。任何一项缺失或冲突均拒绝补记，须先核对收款事实。

新代理收益入账采用同一收款核对条件；SQLite 候选查询和最终入账事务均检查，避免仅靠订单状态释放佣金。已存在的收益记录不会因为新增校验发现历史支付尝试缺字段或状态不一致而自动冲减；此类历史差异应单独核查，不得推断真实退款。

自动化回归覆盖内存及 SQLite 两种仓储的待确认、到账不足、流水错配、恢复确认、重复核算及历史已入账保护。该测试只证明本地规则，不代表生产收款记录已经逐笔对账。

## 已验签付款结果重放

若订单已记为付款成功，但支付尝试仍停在旧的待确认状态，渠道已验签通知或官方查询可在同一事务中补齐支付尝试。必须核对订单、渠道、交易流水与足额到账；支付宝取码阶段的订单号允许作为尚未替换的临时引用，另一笔真实交易流水或不同到账金额则拒绝自动覆盖。缺少原付款时间时不猜测时间；已记退款的支付尝试也不得被付款重放改回已支付。

该修复不重复写付款账本或付款通知。若履约早已成功而新佣金入账此前因凭证不一致被挡住，修复后立即按现有幂等规则核算一次。内存和 SQLite 回归均覆盖重复调用、冲突记录、退款保护；另以模拟支付宝官方查询验证完整回查入口。生产历史差异仍须独立抽样核对。
