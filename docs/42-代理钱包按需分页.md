# 代理钱包按需分页

状态：已在本地重构分支实现并通过自动化测试，尚未部署生产。

## 原问题

打开单个代理的资金页时，旧接口 `/workspace/api/wallets/{merchantId}` 同时返回余额、全部充值申请、全部提现申请和全部资金流水。界面虽然用三个标签展示，但浏览器进入页面时已经读取并构建了所有历史记录。代理交易越多，接口负载、JSON 体积和 DOM 构建时间越长。

## 现在的读取方式

- `/workspace/api/wallets/{merchantId}` 只返回采购余额、收益余额、冻结和待核收益等摘要。
- 新增 `/workspace/api/wallets/{merchantId}/history`，使用 `kind=deposits|withdrawals|ledger`、`page`、`limit` 分页读取。
- 进入资金页只请求当前选中的交易标签，每页 20 条。
- 切换充值、提现或资金流水标签时，页码归一并只查询所选类别。
- 切换代理商、进入代理详情或切换资金入口时，历史页码重置，避免把上一代理的页码带入新范围。
- 充值核实、提现审核和流水显示仍使用原有操作与权限；只改变读取路径，不改变资金事务。
- SQLite 新增按租户和业务创建时间排序的组合索引，匹配三类历史分页。

## 安全与兼容性

新历史接口先通过工作台登录鉴权，再执行租户范围校验。平台可查看指定代理；代理账号只能查看自己的记录。对外 Partner API `/v1/wallet` 暂时保持原响应结构，本轮不对代理已经接入的公开接口做破坏性修改。

## 验证

SQLite 集成测试创建多页充值、提现和资金流水，验证摘要接口不再携带历史数组，三类历史分别返回正确分页元数据，资金流水金额仍按元格式化，并确认查询实际下推到仓储分页方法。

本轮没有连接或修改生产数据库，也没有部署服务器。
