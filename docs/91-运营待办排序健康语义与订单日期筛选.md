# 运营待办排序、健康语义与订单日期筛选

## 待办读取规则

首页每类待办直接在数据库按业务优先级和等待时间读取少量记录，同时以同一筛选条件返回全量数量。禁止先取最近 50 条再在内存中排序。

- 异常任务：紧急优先，同级按首次发现时间从旧到新。
- 退款：失败待重试优先，其次是待审核和渠道处理中；同级从旧到新。
- 退款差异：按首次发现时间从旧到新。
- 每日核算：争议单优先，其次待打款和待核销；同级从旧到新。
- 提现：待审核优先，其次待确认打款；同级从旧到新。
- 开票与售后工单：按更新时间从旧到新。

首页每类最多显示四条，并显示全量总数与“查看全部”入口。正常处理中订单仍与异常队列分开。

## 健康状态语义

- 支付卡显示的是“配置就绪”而不是实时支付宝健康探测，并展示配置最近更新时间。
- 供应卡显示最近一次连接验证结果与时间；即使最近验证成功，也明确标记为非实时状态。
- 未执行检测时显示“未检测”，不能用“系统正常”代替。

## 订单日期筛选

订单列表支持两组互不混淆的北京时间自然日范围：

1. 下单开始 / 下单结束：按 `createdAt` 筛选。
2. 付款开始 / 付款结束：按 `paidAt` 筛选；未付款订单不会进入付款日期结果。

结束日期包含当日，服务端转换为下一日 00:00 的开区间边界。服务端严格验证自然日及起止顺序，SQLite 与内存实现使用同一口径。

首页“今日已付”和“履约成功”统计卡会携带当日付款范围及相应状态进入订单列表；收款、退款、佣金金额进入同日资金明细。手动刷新和订单自动刷新不清空当前筛选条件。
