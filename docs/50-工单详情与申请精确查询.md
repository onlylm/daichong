# 工单详情与申请精确查询

## 问题

旧实现打开单个工单时，会先读取该代理的全部历史工单消息，再在应用层筛选当前工单。历史消息增加后，点击“工单详情”的读取量和 JSON 解码量会持续增长。提现工单关联和等级申请防重也存在先读取整类记录再查找目标的情况。

## 本次改造

- SQLite 仓储新增按 `merchantId + ticketId` 精确读取工单消息的方法，并按创建时间和记录编号稳定排序。
- 代理商读取工单详情时，数据库直接排除平台内部备注；平台管理员仍可读取完整会话。
- 提现工单创建和状态同步按 `withdrawalId` 精确定位关联工单。
- 等级申请幂等校验按 `requestKey` 精确查询，待审核冲突按状态精确查询，首条申请说明按工单编号精确读取。
- 新增工单消息、提现申请和等级申请表达式索引，避免历史增长后退化为全表扫描。

## 行为边界

本次只改变读取范围，不改变工单权限、租户隔离、内部备注可见性、消息顺序、提现状态同步或等级申请幂等规则。内存仓储继续使用原有安全回退，生产 SQLite 使用精确查询。

## 验证

SQLite 集成测试同时创建目标工单、无关工单和内部备注，确认：

- 平台管理员按顺序看到目标工单的全部消息；
- 代理商看不到内部备注；
- 打开详情调用精确查询，未退回全代理消息扫描；
- 类型检查及工单、等级、通知和行动中心专项测试通过。

本地分支尚未部署生产。最终发布仍按统一流程先备份生产数据库，再同步应用并执行只读验收。
