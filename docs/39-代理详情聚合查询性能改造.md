# 代理详情聚合查询性能改造

状态：已在本地重构分支实现并通过自动化测试，尚未部署生产。

## 原因

打开一个代理详情时，系统需要展示有效完成订单数、累计供货额和采购余额。旧实现先读取该代理全部订单，再对每一单分别读取支付记录和履约记录，查询量为 `1 + 2N`；采购余额也会加载全部钱包流水后在 Node.js 中求和。随着订单和流水增长，代理管理页会越来越慢。

## 改造

- SQLite 使用单条聚合查询计算有效完成订单数、累计供货额和自收款供货额。
- 统计仍严格要求真实支付成功、真实上游履约成功、非测试订单、未发生普通退款，业务口径不变。
- 采购余额复用钱包数据库聚合，不再把全部流水加载到应用层。
- 内存仓储保留原有扫描实现，仅用于隔离测试；生产 SQLite 走固定数量查询。

## 验证

自动化测试明确断言：等级累计为 1 条数据库查询，采购余额为 1 条数据库查询；同时验证自收款订单、供货金额和扣减后采购余额均与原业务结果一致。

## 后续

订单、资金、通知和财务核心读取已经数据库化。下一阶段继续处理平台首页行动中心中的工单、开票和每日核算单列表，将“全量读取后过滤”改为按状态分页与计数，并补充分层数据量并发验证。
