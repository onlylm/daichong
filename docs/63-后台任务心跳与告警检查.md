# 后台任务心跳与告警检查

## 目的

API 可用不代表支付核对、充值派发、退款回查、Webhook、通知、成本读取和每日核算仍在运行。本版本由独立 Worker 每 5 秒向共享数据库写入一次持久化心跳，并记录每条任务通道的最近开始、最近完成、连续失败和运行中状态。

心跳只保存稳定的内部通道名与 `task_failed` 分类，不保存 SDK 异常原文、支付宝签名请求、上游响应、Session、Token、CDK 或密钥。

## 健康接口

- `GET /health/live`：API 进程存活。
- `GET /health/ready`：API 与存储已就绪；响应中的 `worker` 仅提示 `healthy/degraded/missing/stale/stopped`，不让 API 启动与 Worker 启动形成循环依赖。
- `GET /health/worker`：后台任务专用探针。仅 `healthy` 返回 HTTP 200；其余状态返回 HTTP 503。公开响应只包含心跳年龄、失败通道数和卡住通道数，不公开内部明细。

建议外部监控分别检查 `/health/ready` 与 `/health/worker`。不能只检查首页或 API 端口。

## 管理员后台

平台概览的“现在需要处理”新增“后台任务”队列：

- 正常时显示“后台任务运行正常”；
- 连续失败时显示失败通道；
- 单次执行超过 120 秒时显示卡住通道；
- 心跳超过 15 秒时显示心跳超时；
- 未启动或正常停止时明确显示对应状态。

“查看详情”可查看每条任务通道的执行次数、最近完成时间和连续失败次数。刷新只重新读取状态，不会重放任务，也不会产生资金操作。

## 发布与回滚检查

1. API 启动后先验证 `/health/ready` 为 HTTP 200；此时 `worker=missing` 是允许的短暂启动状态。
2. 启动 Worker，最长等待 15 秒；验证 `/health/worker` 为 HTTP 200 且 `status=healthy`。
3. 登录平台后台，确认“后台任务”卡片可打开且任务通道完整。
4. 停止 Worker 后，确认探针在 15 秒后返回 HTTP 503 和 `stale`。
5. 恢复 Worker 后，确认新的实例心跳覆盖旧实例，状态回到 `healthy`。

本变更不修改订单、资金或履约表，不需要数据迁移；回滚应用时可以保留 `ops_worker_health` 记录，新旧业务账本不受影响。
