## 三、财务字段与兼容约定（第 2、3 项）

### 3.1 两种口径分开

时区保持 `Asia/Shanghai`，日期范围为当天零点（含）至次日零点（不含）。

| 返回字段 | 当前含义 |
| --- | --- |
| `today/daily.saleAmount` | 该日 `paidAt` 的平台代收已确认收款 |
| `today/daily.refundedAmount` | 该日 `refundedAt` 且状态为 `succeeded` 的普通退款与差价退款合计，与订单在哪天付款无关 |
| `ordinaryRefundedAmount` / `priceAdjustmentRefundedAmount` | 上述当日退款按普通／差价分开 |
| `refundTransactions` | 当日成功退款笔数，不是退款订单数 |
| `netSaleAmount` | 当日收款减当日成功退款；可能为负数，不是利润 |
| `paidCohortRefundedAmount` | 当日付款订单截至查询时的累计退款；用于保留原付款批次经营口径 |
| `paidCohortNetSaleAmount` | 当日付款订单原收款减其当前累计退款；不替代发生日净流入 |
| 汇总 `basis` | 解释收退款按发生日，供货、佣金、履约数量仍按付款批次归集 |

只有订单累计退款金额、没有成功退款时间的历史数据，不凭空分配到某一天；历史累计仍可在付款批次字段查看。未成功、结果未知、没有 `refundedAt` 的退款不当作当天成功出款。余额采购退款不混入平台代收现金流。

### 3.2 钻取及分页

`financeDrilldown` 的 `refunds`、`net_receipts` 改为现金流事件明细：

- `entryId`、`entryType`：唯一收款／退款行及类型；同一订单可以有多行。
- `occurredAt`：该笔收款／退款的实际成功时间；不能一律显示订单付款时间。
- `refundId`、`refundType`、`refundReference`：退款定位及追溯；收款行为空。
- `receiptAmount`、`refundAmount`、`netReceipts`：本行发生额，退款行的净流入为负值。
- `orderId`：关联原订单。分页 `meta.total` 是符合范围的事件数，不是订单数。

其他经营指标仍按订单付款批次展示，并返回单独的口径说明。SQLite 新增 `queryFinanceCashflow` 数据库分页和 `refundedAt` 索引；内存兼容实现用于隔离测试。不将前 50 条当成全部数据，也不在 SQLite 空结果时回退读取全部订单。

### 3.3 标准毛利不是真实净利

每日核算返回新增：

- `standardGrossProfit`：核算单供货额减冻结标准内部成本。
- `standardGrossProfitBasis`：明确未扣支付手续费、实际成本偏差、退款及其他费用，不代表实际净利润。
- `platformProfit`：继续返回原值供旧调用兼容，不重新解释为实际净利，不因此改变应付代理金额。

四套餐当前标准内部成本为 108、630、961、3120 CNY；新订单使用当时配置并冻结，既有订单仍按已冻结口径。实际成本、渠道手续费、普通退款、成本退差分别追溯；本次仅修正展示与查询口径，不自动出款，不重写历史财务事实。
