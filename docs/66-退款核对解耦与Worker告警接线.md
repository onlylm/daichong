# 退款核对解耦与 Worker 告警接线

版本：2026-10-01  
状态：代码与自动化测试已完成，尚未发布生产；生产停止/恢复 Worker 与真实告警通道仍需在发布窗口验证。

## 退款对账异常

- 支付宝交易累计退款大于本地已入账退款时，写入独立的 `refund_reconciliation` 财务主记录，不再新建系统售后工单。
- 同一订单只有一条主记录；检测、金额变化、重新打开、解决和旧工单迁移均写入 `refund_reconciliation_event`，不覆盖历史事件。
- 旧版本已经生成的 `refund-reconcile:*` 系统工单自动转为已解决并关联到财务记录；既有工单、公开消息、内部消息和审计不删除。
- 资金管理新增“退款核对”入口，待办中心可直接打开原订单或核对列表；订单详情显示关联待核状态。
- 履约锁只读取财务主记录，不读取工单状态。只有需要与代理商人工沟通时才另行建立售后工单。

## 队列边界

- 待核状态阻止新的充值提交、重新提交、尚未派发的排队任务和新上游 CDK 签发。
- 已经提交上游的 `running` 任务继续查询明确结果，防止上游成功、本地却永久停在处理中。
- SQLite 在 `LIMIT 20` 前排除被锁的排队履约与 CDK 订单；前 20 条均被锁时，第 21 条正常任务仍可执行。

## Worker 健康与告警

- 生产健康脚本同时检查本机 `/health/ready`、`/health/worker`、API/Worker/数据库/缓存容器和公网路由边界。
- 公网 Caddy 继续拦截 `/health*`；健康详情仅限本机探针或登录后台。
- `quefa-healthcheck.service` 失败触发 `quefa-health-alert@.service`，写入独立 journald 错误事件。
- 可选 HTTPS Webhook 只发送单元名、主机名和时间；配置文件必须 root 所有且权限为 `0600` 或更严格，不发送健康响应、订单或凭据。
