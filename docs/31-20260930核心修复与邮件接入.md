# 核心修复与邮件接入交接

本文记录 2026 年 9 月 30 日这一批核心修复，供管理员与后续开发者使用。它不表示第 29、30 号审计中的所有长期架构问题已经完成。发布状态与实际验证结果以本文末尾记录为准。

## 商品与采购

- 管理员使用全局商品表管理，代理保留套餐采购卡片，单个套餐只有一个采购入口，再选择 CDK 或自动直充交付。
- 全局名称、提货价、上架状态为报价依据。保存带版本号，防止旧页面覆盖新设置；上架检查正价、映射、连接与套餐状态。
- 新商品默认下架；补齐六档 Codex 点数草稿，不自动开启、不替管理员定价。已有商品名称与启停选择不再被启动种子覆盖。
- 自动直充仍由订单绑定的上游 CDK 实现，不恢复指定单卡直充。
- 采购请求保存稳定代理订单号。请求超时或页面刷新后先恢复原采购，不换号重复扣款。签发由后台完成，不阻塞采购 HTTP 请求。
- 供应配置暂不可用时保留签发待处理状态并退避，不把未知结果当最终失败。

## 充值与售后

- 代理不能主动取消 queued 或 running；超时、断网、review、未知状态均不可释放资源或重复提交。
- 只有服务端确认上游明确失败并已结束该次尝试，才返回 retry_allowed。自动直充同时开放代理自有页面的充值入口，不给客户上游码。
- 代理重提使用原订单和新履约幂等键；仅网络重传时沿用原键与原请求体。
- 通知任务每十秒扫描一次。新发生的明确失败、充值超过十分钟未结束、付费后五分钟未签发、退款五分钟未确认等进入异常待办并建立关联工单。阈值是提醒阈值，不是自动失败条件。
- 自动工单按异常实体去重，不反复建单；不自动取消任务、退款、改余额或关闭人工工单。现有工单支持回复、内部备注、等待代理、解决、关闭与重新打开。
- 安装前历史异常仍在待办列表可查，不自动批量新建工单或发送追溯邮件。已有测试订单未删除。

## 财务

- 单管理员直接操作，不增加第二人核验。手动增减采购或收益余额必须填写原因、确认当前余额并使用唯一请求号；扣减不得透支。
- 调账生成不可变流水，记录账户、方向、前后金额、原因与操作者。撤销错误调整应再创建反向调整，不删除原流水。
- 查询钱包不再触发记账。履约成功与退款完成事件驱动本单佣金处理。
- 普通部分退款只冲减对应销售差额；平台承担的 price_adjustment 不冲代理佣金，包括补差使支付状态变成 refunded 的情况。
- 不自动补回历史曾错误冲减的佣金。须先核对具体订单，再由管理员明确调账。
- 支付宝退款超时保持 processing 并占用原退款额度。后台按原退款号查询，只有 REFUND_SUCCESS 且订单与金额匹配才记账；查询未确认时只复用原号、原金额有限重试，超过次数留待人工核查，不生成新退款单。
- 重启遗留、没有新恢复标识的 processing 退款仅查询，不自动重新发起付款。

退款查询依据：[支付宝退款查询接口](https://aipay.alipay.com/docs/vibe-pay/ai-web-app-payment-qianyi/api-list/alipay-trade-fastpay-refund-query.html)。HTTP 成功或查询 code=10000 本身不代表退款完成。

## 上游码与代理品牌码

- 管理员订单详情可按需查看仍保存的上游 CDK，查询接口检查管理员身份、禁止缓存并记录访问审计。代理订单响应不返回上游码或上游 CDK ID；直接访问管理员接口返回 403。
- 上游码兑换成功或停用后被清除，不能承诺所有历史订单仍可读；上游记录 ID 留作追踪。
- 代理主账号在合作设置修改 2 至 8 位字母数字品牌前缀，仅影响新签发公开号。
- 当前是品牌前缀加固定四组五位随机十六进制字符，不是任意模板编辑器；不支持自选整串、修改分隔符、分组或随机长度。代理自定义品牌码不等于上游原码。

## 阿里云企业邮箱

管理员进入通知与任务，代理主账号在消息通知配置自己的接收邮箱。

1. 使用 smtp.qiye.aliyun.com，或中国香港线路 smtphk.qiye.aliyun.com；固定 SSL 465，校验证书，不回退明文。
2. 填完整发信邮箱、邮箱客户端安全密码及管理员接收邮箱。密码加密入库，读取配置不返回明文；不要在聊天或工单中粘贴。
3. 保持邮件关闭，保存后点击验证 SMTP 连接。验证仅做连接与认证，不发测试邮件。
4. 验证成功后开启邮件。代理须由主账号填写接收邮箱并主动开启，其他子账号不能修改。
5. 通知包括新异常工单和工单状态更新。邮件只含单号与工作台入口，不含客户凭据、原始卡密、正文内部备注或密钥。
6. 管理员可看最近一百条投递记录。失败指数退避，最多五次后人工重试；关停或变更收件地址后跳过旧地址排队邮件。

邮件采用持久化去重与租约；SMTP 是至少一次尝试，网络结果不确定时仍可能重复到达，不承诺端到端精确一次。未配置时邮件默认关闭，不妨碍交易。连接验证与真实收信需由管理员填好邮箱后验收。

官方配置参考：[阿里邮箱服务器与端口](https://help.aliyun.com/zh/document_detail/36576.html)。企业邮箱适合当前低频通知；量增大后应迁移专用邮件推送服务，避免影响企业日常邮件信誉。

## 性能与安全边界

- 支付查单、钱包充值、CDK 签发、履约、退款恢复、回调和通知拆成独立执行通道；一个慢请求不再阻塞全部后台任务。
- 保留 SQLite 事务与原子领取；没有声称已切换 PostgreSQL 或 Redis。大规模订单查询、归档、分页下推仍需后续专项改造。
- 状态筛选在分页前进行；订单、钱包等动态视图不再被短期页面缓存遮住新状态。弹窗取消保留输入，关闭时清理轮询并归还焦点。
- nonce 存储进共享 SQLite，防止重启或多进程绕过防重放；回调地址 DNS 解析校验公网后固定连接 IP，禁止重定向并设超时。
- notify_url 按登记端点选择投递，不再无视订单选择广播。密钥只留服务端。
