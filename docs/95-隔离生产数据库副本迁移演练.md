# 隔离生产数据库副本迁移演练

版本：2026-10-02
状态：已在本机对获准下载的真实历史生产快照执行恢复与候选初始化，输入及关键记录摘要不变。未部署生产；真实配置解密、容器网络隔离及上线前最新快照复验仍未完成。精确版本与证据统一见 [100-首发候选验收清单](100-首发候选验收清单.md)。

## 目标

在发布前确认候选代码可以读取现有生产结构、完成必要的兼容迁移并正常提供核心只读页面，同时证明候选启动不会篡改资金及履约事实。演练不连接支付宝或上游，不替换线上数据库，也不产生真实订单、退款、CDK 或打款。

## 强制边界

1. 输入只能是一致性备份，不能是仍在运行的 SQLite 主文件，也不能用普通文件复制替代 WAL 在线备份。
2. 必须显式设置 `AUDIT_ISOLATED_SNAPSHOT=true`；缺少该标记立即拒绝。
3. 若输入文件与配置中的线上数据库是同一路径、符号链接或硬链接，立即报 `live_database_snapshot_forbidden`。
4. 输入以只读方式打开，先检查完整性和逻辑摘要，再通过 SQLite Backup API 恢复到独立临时目录。
5. 候选 Runtime 和 HTTP 应用只连接临时恢复库。检查通过或失败后均关闭应用、数据库并删除临时目录。
6. 演练前后复核输入文件的文件摘要和逻辑摘要；任何变化均按失败处理。
7. 建议在 `--network none`、只读根文件系统、只读快照挂载和临时 `/tmp` 中运行候选镜像。
8. 同时硬性要求 `NODE_ENV=production`、`EXECUTION_MODE=production`、`STORAGE_DRIVER=sqlite`；测试/内存模式在读取快照前拒绝，不能以空内存应用启动成功冒充生产副本兼容。报告包含上述实际运行模式。

## 记录保护

启动前后必须逐字段稳定比较以下记录：

- 订单、支付尝试、履约、CDK、退款、账本、结算；
- Outbox、Webhook 投递；
- 钱包流水、充值、提现、余额调整；
- 每日核算、开票申请、开票补差支付与核对；
- 订单成本、成本补差、支付事件及历史加密币支付记录。

候选启动允许发生的变化仅限确定的配置兼容迁移，例如撤销演示凭据、补齐四款商品目录、代理 API 默认策略、供应映射及旧退款差异记录迁移。工具会对全部记录类型生成独立摘要；任何未在允许集合内的变化均失败，不会因为关键财务摘要未变而被忽略。

## 自动验证

`tests/production-snapshot-rehearsal.test.ts` 覆盖：

- 生产候选仅在临时恢复库启动；
- `/health/ready`、`/developers`、`/developers/openapi.yaml` 可用；
- 订单、支付尝试和钱包流水启动前后完全一致；
- 输入快照摘要及原始字节完全不变；
- 报告不泄露订单号、业务数据或测试敏感字段；
- 把输入同时配置为线上数据库时硬拒绝且不改文件；
- 缺少隔离安全标记时硬拒绝且不改文件。
- 非生产执行模式或内存仓储时在打开源文件前拒绝，原备份字节保持不变。

本地通过只证明工具行为和测试样本正确，不能替代真实生产快照、真实数据规模和服务器文件权限验证。

## 生产执行与留证

实际命令见 `deploy/production/README.md`。每次候选发布至少保留：

- Git 提交号及候选镜像不可变摘要；
- 输入快照 SHA-256 和备份生成时间；
- 演练开始、结束时间及退出状态；
- 工具输出的脱敏 JSON；
- 若失败，保留日志但不得复制订单载荷、Session、CDK、支付签名或密钥。

真实生产快照首次通过后，仍需人工抽样核对订单、支付、退款、代理钱包、佣金和每日核算总额。完成这些证据前，不得将状态写成“生产迁移已验收”。
