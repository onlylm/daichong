# 订单详情审计按需分页

## 问题

充值中的订单详情会按照退避策略自动刷新进度。旧实现每次读取详情时，都会先读取该代理商的全部审计记录，再在应用内筛选当前订单、履约任务和退款记录。代理历史越多，打开详情及后续轮询越慢。

## 修改

- `GET /workspace/api/orders/{id}` 不再返回人工操作审计，订单进度轮询只读取订单、履约、退款、收款和核算所需数据。
- 新增平台管理员接口 `GET /workspace/api/orders/{id}/audit?page=1&limit=20`。
- 审计面板默认折叠；管理员展开面板后才发起查询，支持上一页、下一页。
- 查询条件限定为当前订单，以及该订单的履约任务和退款对象；数据库直接分页，不在应用内遍历代理商全部历史。
- SQLite 增加 `kind + merchant_id + targetId + createdAt` 索引。
- 代理商无权调用平台审计接口，上游兑换码的权限隔离规则不变。

## 结果

实时进度仍按原频率刷新，但不再反复携带和扫描审计历史。完整审计没有删除，仍可在订单详情中按需追溯。

## 自动验证

- 订单详情响应不含 `audit`。
- 45 条目标订单审计可按 20 条一页读取，其他订单审计不会混入。
- SQLite 路径不调用 `listAudit` 全量读取。
- 工作台脚本包含折叠触发、错误重试和审计分页入口。
