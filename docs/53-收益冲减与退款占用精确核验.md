# 收益冲减与退款占用精确核验

## 问题

代理商发起收益划转、提现、采购或平台处理退款后，系统需要保证已释放佣金与订单退款保持一致。旧实现会读取该代理全部 `wallet_credit`，并对每一笔逐单查询订单、付款、履约和退款。历史订单增长后，这类资金操作会在 SQLite 写事务内产生大量查询。

支付设置中的异常付款列表也会读取全部加密货币付款记录后再截取前 200 条，导致无关历史记录被解码。

## 本次改造

- SQLite 直接关联收益确认、订单、真实付款和成功履约，只返回目标佣金低于已确认佣金、确实需要冲减的记录。
- 单笔订单回调触发重算时，查询进一步限定到该订单；全代理重算仍保持完整正确性，但数据库只解码异常记录。
- 提现、收益划转和打款审核前的退款占用判断改为 `EXISTS` 查询：只要任一已释放收益订单存在 `requested/approved/processing` 退款即拒绝资金流出。
- 支付异常复核列表按 `failureCode` 非空、更新时间倒序和 200 条上限在数据库筛选。

## 业务规则保持不变

- 普通退款减少代理收益；价差退款不减少代理收益。
- 自收款采购订单、测试订单、模拟履约和未成功履约订单不能产生可提现收益。
- 存在待确认退款时，不允许收益划转、提现或确认提现打款。
- 冲减记录继续采用确定性编号，重复重算不会重复扣减。

## 验证

SQLite 集成测试构造平台实收、真实成功履约、已释放收益和部分普通退款，确认收益从 ¥25.00 精确冲减到 ¥15.00；随后插入待处理退款，提现申请被阻止。测试同时确认没有退回全量收益、逐单订单、付款、履约或退款列表读取。

本地分支尚未部署生产。最终部署前应在生产只读副本上对比每个代理的收益余额、冲减候选和待退款占用结果。
