# Quefa 代理商后台使用手册

版本：v0.1（非技术用户版）

## 0. 你在这个系统中的角色

代理商的核心工作是推广和销售：在自己的商城展示商品、设置允许范围内的终端售价、查看订单和履约、提交退款申请、核对销售差价和结算。买家的钱统一进入 Quefa 自有支付宝，Quefa 负责确认到账、履约和原路退款。

代理商不需要提供支付宝账号，也不会看到支付宝私钥、应用证书、Quefa 上游或真实成本。后台中的“应用密钥”只是商城调用 Quefa 接口的凭证，不是支付密钥。

## 1. 登录与安全

使用公司分配的个人账号登录，不要共用账号。首次登录后启用双重验证。不要把 API 密钥粘贴到聊天、工单、截图或浏览器脚本中；完整密钥只在创建时显示一次，遗失后应轮换，不能“找回原文”。发现异常订单、陌生 IP 或密钥泄漏时，先停用对应应用密钥，再联系平台管理员。

角色建议：代理商管理员负责账号和密钥；运营查看商品/订单/履约；客服处理失败原因；财务查看退款、台账、结算和开票；审计员只读。

## 2. 商品中心

商品列表显示是否授权、Quefa 供货价、允许的最高销售价、单笔上限和销售状态。代理商商城售价必须在允许范围内。商品“暂停”时不能新开单，但已有订单仍可查询和处理。看不到商品通常表示未授权或已暂停，请勿用其他代理商的商品编码尝试下单。

## 3. 订单中心

订单详情按时间展示：创建、等待付款、Quefa 支付确认、履约提交、履约结果、退款和结算。常见支付状态：等待付款、已支付、已过期、部分退款、已退款。买家展示付款截图不等于到账，必须以 Quefa 返回的“已支付”为准。代理商不用查询支付宝流水。

查询订单可使用 Quefa 订单号、代理商订单号（API 字段仍为 `merchant_order_no`）、日期和状态。导出文件包含敏感经营信息，下载链接会过期；不要转发给无权限人员。

## 4. 履约中心

只有已支付订单可以提交履约。提交 Session 前应让用户确认账号邮箱。后台只显示脱敏邮箱，不展示完整 Session。状态含排队中、处理中、成功、失败。

失败处理：

- Session 无效：请用户重新登录后再提交；
- 账号已有订阅：确认是否选错账号；
- 地区不支持：更换合规地区账号；
- 支付受阻/等待验证：不要重复提交，转人工复核；
- 上游暂时不可用：系统会安全重试，保持查询；
- 其他：把订单号和失败码发给客服，不要发送 Session。

履约已提交但结果未知时禁止反复点击。系统只会查询原任务，避免重复消费。

## 5. 退款与补差

普通退款用于取消整笔或部分交易；补差退款用于成交价调整，履约成功事实仍保留。申请时必须选择类型、金额和原因。高风险退款需要审核，状态依次可能为待审核、已批准、退款中、成功、失败或驳回。

已经在履约中、结果未知或履约成功的订单不会直接自动退款，需 Quefa 运营核查。不要让用户重复提交多个退款号。退款由 Quefa 使用自己的支付宝原路执行，渠道确认成功后才算退款完成。

示例：买家向 Quefa 付款 135 元，Quefa 供货价 110 元，原代理商销售差价 25 元；补差退款 10 元后，代理商销售差价变为 15 元。

## 6. 财务台账与对账

后台分别显示买家付款、Quefa 支付渠道实际收款、Quefa 供货价、普通退款、补差退款、代理商销售差价和代理商待结算。支付手续费、上游真实成本、Quefa 毛利属于 Quefa 内部数据，不在代理商后台显示。

每日对账应核对：订单数量、付款金额、退款金额、补差金额、待结算变化。出现“账实差异”标记时先查看差异原因，不要手工修改订单金额；提交对账工单并附订单号、支付流水号和日期。

## 7. 结算单

结算单经历草稿、复核、确认、付款中、已付款。确认前检查结算周期、订单明细、退款/补差和上期调整。结算单封存后不可修改。

结算后发生退款时，旧结算单仍保持原样，系统会在下一期生成冲正或负向调整。这是为了确保历史打款凭证和账务记录一致。若调整后当期金额为负，将按合同结转或另行处理。

## 8. 开票

从已付款订单详情点击“申请开票”。平台当前只受理企业抬头，公司名称、纳税人识别号、收票邮箱和联系人均须填写，发票类目固定为“技术服务费”。发票金额应填写代理商面向客户的实际成交金额，不要求等于 Quefa 供货价。

系统在申请时计算发票金额的 5% 作为代理商承担的补差价。例如发票金额为 ¥1000，代理商另付 ¥50。该 ¥50 使用独立支付宝支付单，支付宝账单显示“订单补差价”，不向客户收取，也不计入原订单、代理佣金或每日核算单。点击“支付提交”并经支付宝验签确认到账后，页面才显示“开票申请已提交，请等待平台处理”。

平台可开始处理、退回补充资料或登记开票完成。退回资料不重复收取 5%；代理商修改公司名称、税号或收票信息后重新提交。发票号码、处理说明、补差价支付流水和全部状态变化均保留，不能删除历史记录。

## 9. Webhook 与接口应用

“应用与密钥”供代理商技术人员使用。可查看应用状态、出口 IP 白名单、Webhook 地址和最近投递结果，但后台永远不再显示完整 `client_secret`。该密钥只能调用 Quefa API，不能用于支付宝。轮换密钥时新旧密钥可短时并行，确认商城已切换后再吊销旧密钥。

Webhook 失败会自动重试。技术人员修复接收服务后，可在投递记录中人工重放；同一投递号应由商城去重。

## 10. 日常与异常处理清单

每天：查看失败履约、待审核退款、Webhook 死信、对账差异和待结算余额。每周：检查账号权限、停用离职人员账号、复核密钥使用 IP。每月：确认结算单和开票资料，参加备份/恢复或业务连续性抽查。

遇到事故时：先停止高风险动作，记录订单号、时间、页面状态和请求编号；不要截取完整密钥或 Session；联系 Quefa 支持并说明影响范围。未经授权不要重复退款、强制改状态或删除记录。
