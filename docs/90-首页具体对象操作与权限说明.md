# 首页具体对象操作与权限说明

## 目标

首页待办不是只读数字，也不以跳到大列表作为“处理”。服务端返回当前账号对各类待办的操作能力，前端据此对具体业务记录提供动作，同时所有写接口继续执行后端权限校验。

## 退款待办

- 每条待办携带原退款申请 `refundId`。
- `requested` 显示“审核退款”，直接审核该退款申请。
- `failed` 显示“重试退款”，复用同一退款申请和退款号重试，禁止创建第二笔退款。
- `processing` 只允许查看进度，避免对渠道结果未知的退款重复发起。
- 补差退款与普通退款继续使用各自的确认说明和佣金口径。

## 核算待办

- 只有 `platform_admin` 可在首页执行“确认打款”和“到账核销”。
- 平台财务、审计等只读角色只能“查看核算”。
- 后端 `confirmPaid`、`reconcile`、`cancel` 仍独立验证平台管理员角色，前端隐藏不是安全边界。

## 其他待办

- 提现操作依据服务端 `canReviewWithdrawals` 能力；无权限时只显示查看入口。
- 开票操作依据服务端 `canManageInvoices` 能力；无权限时只显示查看入口。
- 能力由服务端依据账号角色和权限表计算，避免前端与后端各自猜测。

## 回归覆盖

- 平台管理员：退款、提现、核算、开票均可处理。
- 平台财务：可处理退款、提现和开票，不可登记或核销每日核算。
- 平台审计：相关待办只读，不显示资金写操作。
- 首页退款按钮使用已有退款申请，不再仅打开订单后要求管理员自行寻找申请。
