# 历史系统工单有界迁移

通知 Worker 过去每 10 秒都会读取并解码全部历史工单，以迁移旧版自动异常工单。工单增长后，这会在 API 与 Worker 共用 SQLite 时造成不必要的读锁、JSON 解码和页面卡顿。

现在迁移规则为：

- 每轮只按 ID 读取最多 100 条仍处于活动状态的旧系统工单；
- 使用数据库内持久化游标继续下一批，Worker 重启不会从头扫描；
- 迁移结束写入完成标记，后续轮次不再查询历史工单；
- 退款差异旧工单仍由独立退款核对迁移负责，不混入普通运营异常；
- 原工单和消息继续保留追溯，业务状态改由独立运营异常记录管理。

本改动不删除历史工单，不改变新工单、退款核对、充值锁或资金状态。
