# 生产上游配置与代理商接入发布

日期：2026-09-27。本文是平台内部发布清单，不提供给代理商；代理商只领取 `/developers` 下的公开开发者中心、OpenAPI 与对应密钥。

## 一、生产上游配置

生产地址固定为：

```text
OpenAPI  https://zovocard.com/openapi/v1
CDK API  https://zovocard.com/api/v1/cdk
```

模板见 `deploy/production-upstream.env.example`。生产 API Key、Webhook Secret 和直充付款资源编号必须从工作台“生产供应”页面或服务器 Secret Manager 写入，不进入源码、镜像、聊天、工单或代理商配置。

切换顺序：

1. 生产服务器使用 `NODE_ENV=production`、`EXECUTION_MODE=production`，初始保持供应连接和全部支付通道关闭。
2. 保存生产地址和生产凭据，将服务器固定出口 IP 加入上游白名单。
3. 执行只读“测试连接”，确认余额与 GPT 套餐接口正常。
4. 只同步 GPT 套餐，以 `registry[].purchasable` 与对应 `plans[acc_plan_key].enabled` 共同判断可售；其他产品即使出现在上游响应中也不得上架。
5. 配置公开 HTTPS 回调 `/internal/webhooks/recharge`，验证原始请求体 HMAC、重复事件和乱序事件。
6. 检查 Plus、Pro 5x、Pro 20x、Pro 50x 四项 CDK 映射；全部保持默认停用。
7. 先创建内部验收代理，为一个商品配置真实供货价并明确启用；再启用对应全局映射、单一支付通道和生产供应连接，完成一笔最小金额订单。
8. 核对付款、上游扣费、订单终态、下游 Webhook 和财务分录，再开放其他代理或商品。CDK 另做一张有上游资金上限的验收单。

“保存生产地址”“连接已启用”和“允许真实提交”是三件不同的事。保存地址不会请求上游；测试连接只读；生产模式下只有部署级开关、生产供应连接、已核验真实付款和可售商品同时满足时，Worker 才会执行真实写操作。`controlled` 模式另外要求白名单、额度和逐笔批准。

## 二、白标边界

- 代理商与客户只访问 Quefa 域名。
- 代理商浏览器只访问其自己的后端；代理后端再签名调用 Quefa。
- ZovoCard 地址、API Key、供应订单号、原始 `ZC-` 码和卡数据不得出现在代理响应、Webhook、HTML、日志或工单。
- 平台向客户签发代理品牌公开号；对应上游码加密保存，成功或停用后清除。
- CDK 的 `preview → preflight → redeem → result` 全程由 Quefa 服务端代理，保持固定出口 IP 和稳定 `X-Redemption-Device`。

## 三、代理商接入交付包

代理商只需获得：

1. 生产或沙箱 API Base。
2. `partner_id`、`key_id` 与只显示一次的 `client_secret`。
3. 已授权商品与实时供货价。
4. `/developers` 可视化开发者中心。
5. `/developers/openapi.yaml` 机器可读定义。
6. 签名示例、自建兑换指南和 Webhook 验收地址。

推荐 API 验收航道：创建服务端密钥 → 使用平台收款创建订单 → 回调验收；无需预存采购余额。只有验收代理自收款时才先核实采购余额实际到账。平台代收订单不扣采购余额；代理自收款订单按供货价扣采购余额。两种模式都由 Quefa 服务端履约。

## 四、当前生产边界

运行时已支持生产启动校验、独立管理域名、MFA、正式密钥、后台托管支付和真实供应适配器。当前按单服务器低订单量使用 SQLite WAL 与一致性备份；扩大为多节点或显著提升订单并发前必须迁移 PostgreSQL，并完成异机加密备份、外部告警、退款与渠道对账自动化。

首次开放仍应保持小范围、单商品和可人工回滚，确认真实链路后逐步扩大；不得因为系统处于生产执行模式就跳过通道验证。
