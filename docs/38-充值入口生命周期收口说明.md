# 充值入口生命周期收口说明

状态：已在本地重构分支实现并通过自动化测试，尚未部署生产。

## 修复目标

订单取消、退款、过期或履约终态必须直接约束公开充值入口，不能只依赖页面按钮或等到创建任务时才拒绝。公开链接仍使用不可猜测签名，但签名正确不再代表订单永远可提交。

## 服务端规则

- 订单已关闭、过期、全额退款、发生普通部分退款、归档，或存在待处理退款时，页面和状态/凭据接口返回 HTTP 410，且不再收集凭据。
- 纯补差退款只调整价格，不消耗原订单履约权益，因此订单尚未履约时仍可使用入口。
- 充值排队或处理中，页面只显示已确认的进度并自动刷新，不再显示凭据表单。
- 充值成功后显示只读成功结果，预检和提交接口拒绝再次使用。
- 本地超时、未知结果或没有安全重提依据的失败只显示核对提示，不开放输入。
- 只有上游明确失败且 `canResubmit` 校验通过，或管理员对尚未派发任务选择允许重提，原入口才重新开放。
- 通用 CDK 预检与兑换共用相同的订单、退款和履约资格判断；失效码不会先调用上游预检再在兑换阶段才失败。

## 数据与安全边界

本次不保存新的 Session 数据，也不改变现有短期加密凭据生命周期。规则在每次页面、预检、提交和状态请求时读取最新订单、退款和履约状态，因此旧链接无法绕过最新退款或取消结果。

## 自动化验证

新增公开入口专项测试，覆盖全额退款失效、普通部分退款失效、纯补差退款保留权益、进行中禁止重复提交、成功后关闭输入，以及上游明确失败后重新开放原链接。
