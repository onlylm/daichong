# 每日核算打款前一致性复核

## 目标

每日核算单仍然只负责生成待付款快照，不会自动向代理商打款。平台管理员在线下完成实际付款后，登记付款流水前必须再次确认快照所含订单的收益没有因退款或财务纠偏发生变化。

代理商被暂停或关闭后，已完成订单形成的历史应付佣金仍要进入核算单。账户状态限制新业务，不抹去已有资金负债；生成单据不会自动付款，管理员仍需凭真实外部付款流水人工确认。内存和 SQLite 两种存储均按这一规则筛选，关闭账号的订单也保留账务追溯。

## 打款前检查

平台登记核算单已付款时，系统在同一个数据库事务内依次检查：

1. 付款流水号未被其他核算单或提现记录使用；
2. 该代理商不存在仍可能冲减已释放收益的待处理退款；
3. 按核算单内订单号重新汇总当前收益，结果与生成核算单时的收益快照完全一致；
4. 逐订单核对收益确认记录与 `earning_release` / `earning_reversal` 钱包分录净额，要求每个订单恰好一条确认记录且金额一致；其他订单的正余额不能填补缺失的分录；
5. 当前代理收益余额仍足以覆盖本次应付金额。

任一条件不满足都不会写入核算付款流水，也不会扣减收益余额。

## 异常处理

- 有退款待确认：先在退款核对模块处理退款，再重新登记付款；
- 核算单内收益已变化：作废旧核算单，相关订单在下一核算周期重新生成；
- 订单收益记录与资金流水不一致：暂停登记打款，检查该订单是否缺少收益释放或冲减分录；核实并修复原始账务后重新生成核算单，不得借用其他订单余额绕过；
- 总收益余额不足：核对退款、纠偏及其他已付款核算单后再处理；
- 付款流水号重复：核实真实外部付款记录，不得换一个虚假流水号绕过检查。

## 性能与隔离

SQLite 使用代理商 ID 与核算单订单 ID 精确汇总收益及关联钱包分录，不扫描全部历史资金记录；订单较多时按最多 400 个 ID 分批查询，并按订单引用建立局部索引。内存仓储执行相同的代理隔离规则。新的其他订单收益即使让代理总余额足够，也不能掩盖旧核算单内部金额已经变化或收益分录缺失的事实。

## 回归覆盖

- 待处理退款阻止核算单登记付款；
- 核算单订单收益下降、同时出现无关新收益时仍阻止付款；
- 拦截失败后核算单状态和资金流水保持不变；
- SQLite 生成及付款复核不回退到逐订单历史全扫描；
- 正常核算单仍可人工登记付款并继续核销。
- 暂停、关闭代理商的历史合格订单继续生成待付款核算单；单据生成前钱包不扣款，人工确认后才扣减。
- 内存与 SQLite 均拦截“订单收益记录有金额但关联收益释放分录缺失、由其他订单余额填足”的数据异常；
- 内存与 SQLite 均拦截“订单收益记录已减少但冲减分录缺失”的部分写入；401 个订单号跨批查询时仍正确隔离代理商。
