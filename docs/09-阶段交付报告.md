- 订单、模拟支付、Session AES-256-GCM 加密、终态清理、模拟履约、退款申请/模拟完成。

- API/Worker 共享 SQLite WAL 持久化沙箱，覆盖订单、支付尝试、履约、退款、幂等、Outbox 和 Webhook Delivery；重启后可恢复。
- `GET /v1/orders` 订单分页和支付状态筛选。

- 沙箱代理商凭证签发命令，为每个代理商生成独立 API/Webhook secret，完整 secret 仅显示一次。
- 业务范围收敛为直接充值与 Quefa CDK；客户使用 Quefa 充值页，代理商示例不再代收 Session。
- 代理品牌公开号与底层凭证加密映射，底层码不会进入代理商 API、客户页面或 Quefa 对外 Webhook，成功兑换后立即清除。

- 供应回调先验签、按稳定事件 ID 持久化去重，再更新充值状态；对外错误统一映射为 Quefa 业务码。
- Quefa 内部充值供应管理页与受保护 API，支持加密保存供应连接、连接测试、余额查询、GPT/Claude/Grok 套餐同步、商品映射和脱敏对账；配置变更可被 API/Worker 动态读取。
- 生产目标新增供应连接、套餐快照和商品映射迁移，三张表全部为平台内部资源并撤销 `PUBLIC` 权限。
- 独立内部 OpenAPI 契约及自动化边界检查；系统没有虚拟支付工具创建、敏感资料查询、余额操作、退款、冻结或删除接口。

## 验证结果

- `npm run check`：通过（类型检查、47 项自动化测试、构建）；本轮复核及缺口见 `13-项目复核与完善报告.md`。
- 自动化测试覆盖：签名规范、过期时间戳、Nonce 重放、幂等重放/冲突、跨租户订单/退款/台账/结算、订单分页、沙箱付款页、SQLite 跨运行时持久化、支付尝试持久化、Session 加密清理、direct 白标充值、QF CDK 签发/兑换与底层码防泄露、真实供应适配器请求契约、供应回调验签/持久化/幂等、代理商 Webhook 实际投递、RBAC 租户隔离、135/110/10 财务示例、结算后负向调整、OpenAPI 解析、平台级支付配置数据库边界和支付内部字段防泄露。
- `npm audit`：0 个已知漏洞。
- 本地构建产物启动成功，`/health/live` 与 `/health/ready` 均返回 HTTP 200；持久化沙箱就绪响应标识 `sqlite-sandbox`。
- 已完成 API、Worker、代理商示例三个独立进程的模拟全链路联调：商品查询 → 开单 → 打开付款页 → 确认支付 → 查单 `paid` → 进入 Quefa 充值页 → Worker 成功 → 收到并验签 `order.paid`、`fulfillment.succeeded` Webhook。
- Node.js 签名示例输出与固定向量一致。
- 敏感模式扫描未发现私钥、真实 API Key、JWT/Session 或生产密码。
- 当前主机未安装 Docker、PostgreSQL 客户端、PHP 或可运行的 Python 解释器，因此 Docker Compose 实际启动、PostgreSQL 迁移、PHP/Python 示例运行仍需在具备相应环境的 CI 或开发机补验；原生 Node.js 三进程链路已经实测。

- 真实 PostgreSQL Repository 与 Redis 连接尚未接入生产运行时；当前 API/Worker 使用 SQLite WAL 共享沙箱数据，不得将 SQLite 当作生产资金系统。
- 已有充值供应配置的内部管理页，但代理商完整后台、平台人员登录/MFA、细粒度 RBAC 和 Break Glass 流程尚未实现；当前平台管理令牌仅适合开发/预生产受控入口。

- KMS/Secret Manager、WAF、监控告警、备份、PITR、恢复演练、压测和渗透测试尚未落地。
