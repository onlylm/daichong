# 代理工作台与开放平台双入口规则

版本：2026-10-01

## 1. 基本原则

代理商不必开发网站才能使用 Quefa。平台提供两种并行入口：

1. **代理工作台**：适合直接运营，在浏览器完成下单、平台收款、CDK、自动直充、进度查询、资金、开票和工单处理。
2. **开放 API**：适合已有商城或需要自定义品牌体验的代理商，由代理商服务端签名调用 Quefa，客户浏览器不得持有 API 密钥。

两种入口不是两套账户，也不互相排斥。它们共用同一代理身份、商品授权、订单、采购余额、收益余额、佣金流水、退款、开票和工单记录。代理商可以先使用工作台，之后接入 API；也可以同时使用。

## 2. 代理工作台能力

不开发网站时，代理商仍可：

- 查看四款可售套餐和实时代理供货价；
- 选择 CDK 或自动直充方式创建订单；
- 使用平台收款链接完成客户付款；
- 输入凭据前查看兑换码对应套餐，预检后核对账号当前套餐与目标套餐；
- 查看充值阶段、失败原因和是否允许重新提交；
- 查看余额、佣金、资金流水与每日核算单；
- 按订单申请开票并提交工单。

代理工作台使用登录会话和角色权限，不使用开放 API 的 HMAC 密钥。

## 3. 开放 API 能力

选择自建时，代理商在自己的服务端实现：

- 商品同步、下单和订单查询；
- 自有品牌付款页或平台付款链接展示；
- CDK 交付或自动直充凭据提交；
- Webhook 验签、事件去重和查询兜底；
- 失败后按 `retry_allowed`、`next_action` 和 `fallback_recharge_available` 决定是否重新开放原订单入口。

API 默认可创建服务端应用密钥，无需先申请或预存。采购余额为零时只能使用 `platform_collect`；只有采购余额实际到账且代理具备相应授权时才能使用 `agent_collect`。默认开放不等于取消风控，平台仍可停用泄露、滥用或异常的密钥。

## 4. 数据一致性

- 工作台下单和 API 下单都进入统一订单表与资金账本。
- 同一业务订单只能使用一个稳定的代理订单号；API 重试必须复用幂等键。
- 从工作台切换到 API 不迁移历史数据，也不重新计费。
- 平台管理员在代理管理中心看到的是该代理的完整合并视图，不按入口拆账。
- 支付、充值、退款、收益红冲、开票和每日核算均以服务端状态为准，页面缓存或浏览器跳转不能改变账务事实。

## 5. 品牌边界

直接使用工作台时显示 Quefa 平台界面。选择开放 API 时，代理商可以自行实现品牌页面和客户入口；Quefa 只返回公开业务状态，不返回上游原始 CDK、供应商身份、完整卡号、密钥或内部排障数据。自动直充失败时不向客户显示 CDK，而是在最新任务明确允许重提后重新显示代理商自己的充值入口。
