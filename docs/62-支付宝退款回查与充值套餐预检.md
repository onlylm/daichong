# 支付宝退款回查与充值套餐预检

版本：2026-10-01

## 1. 支付宝渠道退款回查

平台对支付宝订单执行两类回查：

- 待支付订单每分钟回查一次；支付宝明确返回 `TRADE_CLOSED` 时，平台订单和支付尝试同步关闭。
- 已支付或部分退款订单每六小时回查一次；当 `alipay.trade.query` 返回累计退款金额时，系统与本地累计退款金额核对。

渠道累计退款金额大于本地记录时：

1. `alipay.trade.query` 的累计金额不包含可安全绑定本地退款单的 `out_request_no`，因此一律不按金额自动完成退款，也不直接改账。
2. 系统在同一数据库写事务中重新读取订单与本地累计，确认仍有差异后创建或更新独立的“退款对账异常”财务记录；每个订单只有一条当前主记录，金额变化写入不可变事件记录。
3. 财务记录保存渠道引用指纹、渠道累计、本地累计和差额，不保存签名请求或密钥；代理侧只看到正在核对，不得到渠道敏感信息。该状态不依赖售后工单，只有确需人工沟通时才另行关联工单。
4. 本地已发起的退款由 `alipay.trade.fastpay.refund.query` 使用原退款 ID 作为 `out_request_no` 精确查询。订单号、请求号、退款金额、订单总额和交易号全部一致后，才完成该退款并沿用其真实退款类型。
5. 管理员确认外部退款后使用人工补登入账；入账达到渠道累计时财务异常自动解决，但异常事件、退款记录、账本和审计记录继续保留。旧版本已经生成的系统工单自动转为已解决并关联到财务记录，既有消息不删除。
6. 全额退款确认后支付尝试标记为已退款、未使用的本地 CDK 禁用、充值入口返回 HTTP 410，并触发既有钱包收益红冲与 Webhook。

差异尚未准确归类期间，订单财务状态维持原值，但履约进入临时安全锁：充值页显示“支付宝退款差异正在核对”，禁止新建、重提或派发尚未提交的充值任务，也不会新签发上游 CDK。已经提交上游的 `running` 任务必须继续查询到明确结果，不能因安全锁停止回查。按准确退款凭证补登后，财务异常转为已解决；补差退款可恢复原充值入口，普通退款则继续遵循退款后的永久关闭规则。

渠道累计核对、差额计算与财务异常记录更新全部位于同一个数据库写事务。人工补登与 Worker 交错时，后获得写锁的一方必须重读最新累计，不能沿用事务外旧差额。该机制不主动发起真实退款，也不会凭同额把普通退款误判成补差退款。

## 2. 兑换码套餐预览

公开兑换页输入或粘贴 Quefa 兑换码后，先调用 `POST /public/cdk/preview`。接口只读取本地兑换码与订单映射，返回：

- `product_code`
- `product_name`
- `target_plan`

此步骤不调用上游、不读取上游 CDK 明文、不提交充值，也不接收 Session。

## 3. 账号套餐预检

用户填写 Session、Access Token 或邮箱凭据并点击“检测账号”后，预检接口返回：

- `account_email`：本次充值账号；
- `current_plan`：上游预检识别到的当前套餐；
- `target_plan`：兑换码或订单对应的目标套餐；
- `product_name`：面向用户展示的套餐名称。

页面必须同时展示“当前套餐”和“本次兑换”，由用户确认账号与套餐后才能提交。若上游没有返回当前套餐，页面显示“未识别”，不得自行猜测。

公开兑换页和代理商工作台使用同一套预检结果。平台不将 Session 明文或作为长期业务档案保存；异步履约所需凭据仅进入既有短期加密队列，并按任务清理规则销毁。
