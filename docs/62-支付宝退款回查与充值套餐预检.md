# 支付宝退款回查与充值套餐预检

版本：2026-10-01

## 1. 支付宝渠道退款回查

平台对支付宝订单执行两类回查：

- 待支付订单每分钟回查一次；支付宝明确返回 `TRADE_CLOSED` 时，平台订单和支付尝试同步关闭。
- 已支付或部分退款订单每六小时回查一次；当 `alipay.trade.query` 返回累计退款金额时，系统与本地累计退款金额核对。

渠道累计退款金额大于本地记录时：

1. 若只有一笔金额完全匹配的本地处理中退款，完成该退款，不再重复创建记录。
2. 若没有本地处理中退款，按差额创建“渠道已退款”补登记录。
3. 多笔处理中退款无法从聚合金额唯一对应时，不自动猜测，由各退款单的精确查询任务继续核对。
4. 全额退款后支付尝试标记为已退款、未使用的本地 CDK 禁用、充值入口返回 HTTP 410，并触发既有钱包收益红冲与 Webhook。

所有补登都使用确定性幂等键；重复回查不会重复退款或重复记账。该机制只同步支付宝已经发生的事实，不主动发起真实退款。

## 2. 兑换码套餐预览

公开兑换页输入或粘贴 Quefa 兑换码后，先调用 `POST /public/cdk/preview`。接口只读取本地兑换码与订单映射，返回：

- `product_code`
- `product_name`
- `target_plan`

此步骤不调用上游、不读取上游 CDK 明文、不提交充值，也不接收 Session。

## 3. 账号套餐预检

用户填写 Session、Access Token 或邮箱凭据并点击“检测账号”后，预检接口返回：

- `account_email`：本次充值账号；
- `current_plan`：上游预检识别到的当前套餐；
- `target_plan`：兑换码或订单对应的目标套餐；
- `product_name`：面向用户展示的套餐名称。

页面必须同时展示“当前套餐”和“本次兑换”，由用户确认账号与套餐后才能提交。若上游没有返回当前套餐，页面显示“未识别”，不得自行猜测。

公开兑换页和代理商工作台使用同一套预检结果。平台不将 Session 明文或作为长期业务档案保存；异步履约所需凭据仅进入既有短期加密队列，并按任务清理规则销毁。
