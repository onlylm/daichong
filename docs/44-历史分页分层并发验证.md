# 历史分页分层并发验证

日期：2026-10-01 16:07（北京时间）

状态：本地重构分支验证通过，尚未部署生产。

## 验证对象

基准脚本 `scripts/benchmark-history-pagination.mjs` 为同一代理分别生成以下五类历史数据：

- 工单；
- 开票申请；
- 每日核算单；
- 资金流水；
- 操作审计。

每档同时发起 40 个已登录工作台 GET 请求，即每类 8 个请求；请求页大小固定为 20，交替读取前 5 页。脚本验证 HTTP 状态、返回数组上限、总数和查询次数，任何接口返回全量数据、总数错误或多执行分页查询都会直接失败。

运行命令：

```text
npm run bench:pagination
```

任一档 P95 达到或超过 500ms 时脚本以非零状态退出，不能只打印 `targetP95Under500ms: false` 后仍被自动化流程误判为通过。

## 本次结果

环境为本机 Node.js 单进程、隔离临时文件 SQLite WAL、Fastify `inject`，不含真实网络和反向代理。每档结束后关闭连接并删除临时数据库，不读取或写入生产数据。

| 每类历史记录 | 并发请求 | 分页查询数 | 整批墙钟 | P50 | P95 | 最大响应体 |
|---:|---:|---:|---:|---:|---:|---:|
| 100 | 40 | 40 | 71.48ms | 70.92ms | 71.26ms | 17,251 bytes |
| 1,000 | 40 | 40 | 61.75ms | 61.22ms | 61.60ms | 17,253 bytes |
| 5,000 | 40 | 40 | 194.93ms | 194.46ms | 194.83ms | 17,254 bytes |

结论：在本次受控环境下，5000 条/类别时仍满足方案中“普通列表 API P95 小于 500ms”的本地目标。响应体最大值基本保持约 17KB，证明历史总量没有重新进入响应体；40 个请求对应 40 次分页查询，没有出现按总记录数逐条查询。最慢单类数据库分页查询 P95 为 2.56ms。

首次改为文件型 SQLite 后，5000 条/类别的整批 P95 曾达到约 1.36 秒。查询分解确认工单、开票和核算单统一按 `updatedAt` 排序，但缺少无状态筛选时可用的更新时间索引；工单还缺少“未归档 + 更新时间”联合索引。补充全局/租户更新时间索引与归档状态联合索引后，同一基准降至约 195ms。自动化测试通过 `EXPLAIN QUERY PLAN` 固定验证租户列表使用新索引，防止后续无意退化回扫描排序。

## 结果边界

这不是生产性能承诺，原因包括：

- 临时文件 SQLite 位于本机临时目录，不等于生产服务器磁盘、真实 WAL 体积和并行写入压力；
- `inject` 不包含 TLS、Nginx、网络延迟、压缩及浏览器解析；
- 单次运行不能替代长时间 P95/P99 监控；
- 测试数据结构稳定，不包含生产中最大长度备注、复杂审计正文和极端加密字段；
- 浏览器 DOM、切页焦点和移动端渲染由用户最终验收，本脚本不模拟这些行为。

最终发布前应复制脱敏生产快照到隔离目录，在相同服务器硬件上运行只读基准；随后通过反向代理测试并记录接口 P50/P95、SQLite busy/lock、CPU、RSS 和事件循环延迟。不得直接用生产账本运行写入型造数脚本。

## 仍需继续处理的全量扫描

代码复查发现的剩余全量读取分为三类：

1. `finance/costs` 已于后续阶段改成数据库筛选、搜索和分页，并将完整付款凭证延迟到订单详情读取，见《45-成本核算列表服务端分页》；不再属于页面全量扫描遗留项。
2. 支付、退款和开票补差支付 Worker 已改为有界到期队列，见《46-支付与退款Worker有界队列》；CDK 签发、退款停码、退款任务关闭、履约和成本回读也已完成有界候选查询，见《47-充值与成本Worker有界队列》。
3. 充值、提现、开票、每日核算与成本补差的主要请求号/付款流水防重已改为精确索引查询，见《48-回调与资金凭证精确查询》。剩余低频配置与历史兼容扫描继续按“精确查询或唯一约束”原则收口，不能简单截断安全校验范围。

高频 Webhook Worker 的历史投递全量扫描也已改为事务内有界领取，见《49-Webhook投递有界领取》；已完成投递不会再被每秒读取解码。

工单详情的消息读取、提现工单关联和等级申请幂等/待审判断也已改为按业务键精确查询，见《50-工单详情与申请精确查询》；点击单个工单不再解码该代理的全部历史消息。

对外开放平台的订单、财务台账和结算单也已完成数据库游标分页，修正了文档声称分页但台账/结算单实际全量返回的问题，见《51-开放平台历史接口游标分页》。

每日 22:00 核算任务的候选订单、历史归属、收益余额和待付款占用也已改为数据库关联与聚合，见《52-每日核算任务数据库化》；生成核算单仍不自动打款。

代理收益冲减、提现/划转前的待退款占用和支付异常复核列表也已改为数据库精确核验，见《53-收益冲减与退款占用精确核验》。

代理 API 总览、核验充值定位与等级资格充值累计也已改为数据库聚合，见《54-代理API总览与资格聚合》。

开放平台工单和双钱包流水也已服务端分页，见《55-开放平台工单与钱包分页》；代理商仍可直接使用平台工作台，不要求自建系统。

账号列表、最后一名管理员保护和代理员工上限也已改为数据库范围查询与计数，见《56-账号列表与安全计数下推》。

上述三类不得混为一谈。页面读取可以分页，后台任务必须有界，资金防重必须保持全局正确性。
