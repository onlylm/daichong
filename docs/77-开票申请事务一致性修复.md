# 开票申请事务一致性修复

日期：2026-10-01  
状态：本地重构分支已完成并通过自动化测试，尚未部署生产。

## 业务口径

- 一个平台订单只允许存在一份开票申请。
- 开票金额是代理商面向客户的实际开票金额，不强制等于平台订单供货金额。
- 平台按开票金额另收 5% 补差价；支付宝交易说明仍固定为“订单补差价”。
- 公司名称和税号为必填信息；平台仅在补差价到账后收到待处理申请。

## 修复内容

1. 创建申请时，在同一个数据库写事务内重新读取订单并确认仍为已付款或部分退款状态。订单若在请求过程中变为全额退款、关闭或其他不可开票状态，不再生成申请。
2. 同一请求号重复提交时，只有订单、金额和全部开票资料完全一致才返回原申请；不同内容明确返回幂等冲突。
3. 同一订单使用另一个请求号重复提交时，相同资料返回原申请以便继续支付；金额、抬头、税号、收票邮箱、联系人或备注不同则明确提示打开原申请处理，不能静默返回不匹配资料。
4. 代理补充资料和管理员开始处理、退回资料、登记开票完成时，均在事务内重新读取版本和状态。并发请求不能用事务外的旧版本覆盖新结果。

## 验证

自动化测试覆盖：

- 相同订单和相同资料的幂等重放；
- 同一订单不同开票金额的显式冲突；
- 订单在申请事务开始时已变成全额退款，不产生申请；
- 管理员处理期间出现较新版本时拒绝旧请求，并保留较新记录；
- 原有 5% 金额计算、支付宝独立补差交易、晚到付款、重复通知、支付关闭、付款码并发租约和失败重试继续通过。
