# SQLite 持久化端到端验收

更新时间：2026-10-01
适用分支：`refactor/platform-rebuild`

## 验收目标

`tests/sqlite-end-to-end.test.ts` 使用独立临时目录和真实 SQLite 文件，验证关键业务事实不依赖单个 API 或 Worker 进程的内存状态。测试不读取生产数据库、不调用支付宝、不调用真实上游，也不产生真实资金操作。

## 已覆盖链路

1. 代理商使用 HMAC 签名接口创建平台收款订单。
2. 隔离环境模拟已核验的支付宝到账事实，Worker 签发平台 CDK。
3. 代理商通过自建兑换接口提交 CDK 和 Session；数据库只保存加密载荷。
4. 第二代理商读取订单或充值任务均返回不存在，验证租户隔离。
5. 关闭 API 与仓储后，用同一 SQLite 文件重新启动；Worker 恢复排队任务并记录上游终态。
6. 成功履约后清除 Session、查询令牌和上游 CDK 明文，平台 CDK 标记为已消费。
7. 代理收益自动释放一次；重复终态回调不会重复入账。
8. 再次重启后生成每日核算单；核对供货价、成本、平台利润、代理收益和应付金额。
9. 人工登记付款采用幂等重放，同一核算单只产生一条付款流水；随后人工核销。
10. 第四次重启后再次核对订单、履约、CDK、钱包与核算终态。

## 固定断言

- 商品供货价：`¥110.00`
- 平台标准成本：`¥108.00`
- 销售价：`¥135.00`
- 代理收益：`¥25.00`
- 平台基础利润：`¥2.00`
- 核算付款后代理可用收益：`¥0.00`
- `earning_release` 与 `settlement_payout` 各恰好一条
- 代理可见响应不包含原始 Session、上游 CDK、查询令牌或供应标识

## 执行方法

```powershell
npm test -- --run tests/sqlite-end-to-end.test.ts
```

该测试是隔离的持久化业务验收，不替代生产数据库副本迁移演练、真实支付宝受控联调、真实上游沙箱联调、浏览器验收或正式发布前备份恢复验证。
