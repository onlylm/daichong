# CDK 格式与供应追溯隔离复核

## 本轮结论

- 代理主账号已经可以在「合作设置」配置 2–8 位品牌前缀和受控 CDK 模板。
- 模板只能包含一个 `{PREFIX}`，随机段使用 `{RANDOM:n}`；单段 4–12 位、随机位合计不少于 20 位，生成结果限定为 8–64 位大写字母、数字、横线或下划线。
- 配置变更只影响之后新签发的代理品牌公开号；历史公开号继续有效。
- 对外订单、Webhook 和兑换接口只交付代理品牌公开号。自动直充订单不返回公开号，失败后只允许重新开放充值入口，不返回上游原码。
- 上游原始 CDK 仍以加密载荷保存，仅平台管理员可在订单详情按需读取；接口使用 `no-store`，读取动作写入审计记录。

## 本轮修复

订单列表此前虽然不会把上游 CDK 记录 ID 和上游订单号返回给代理商，但搜索条件仍包含这两个供应侧字段。掌握或猜到供应侧标识的代理商可能通过“是否命中订单”侧面确认关联关系。

现已将搜索字段按角色分开：

- 代理商只能搜索平台订单号、代理订单号、代理品牌公开号和脱敏客户邮箱；
- 平台管理员仍可使用上游 CDK 记录 ID、上游订单号进行内部追溯；
- 内存仓储与 SQLite 分页查询采用相同规则，避免测试环境与生产存储行为不一致。

## 回归覆盖

- 自定义前缀与模板签发；
- 低熵、非法字符、缺少或重复前缀占位符拒绝；
- 代理端订单字段不包含上游追溯字段；
- 代理端使用上游 CDK 记录 ID 搜索时不命中；
- 平台管理员使用相同标识搜索时仍能定位订单；
- SQLite 有界分页查询保持固定查询次数。
