# 空队列禁止全历史扫描说明

生产仓储提供 `findDuePaymentOrder`、`findDueRefund` 和 `findRefundInternal` 等索引查询能力。调用方必须按“方法是否存在”决定是否启用旧仓储兼容逻辑：

- 方法存在且返回 `null`：表示当前没有候选，立即结束本轮。
- 方法不存在：仅为旧仓储兼容，允许使用历史列表查找候选。

禁止使用“索引查询结果 `null` 时再全历史扫描”的空值合并写法，否则正常空队列会在每个 Worker 周期读取全部订单和退款历史，数据增长后造成数据库压力和页面/任务卡顿。

本次覆盖支付宝订单回查、托管支付宝回查、退款回查以及按退款编号查找。回归测试显式断言：SQLite 查询能力存在且无候选时，`listOrdersInternal` 调用次数为 0。
