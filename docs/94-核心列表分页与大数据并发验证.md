# 核心列表分页与大数据并发验证

## 本轮改动

- 客户退款与补差退款待审队列改为数据库分页，页面分别保留自己的页码，不再一次读取全部待审退款。
- 普通订单列表先完成数据库分页，再只为当前页订单关联履约与 CDK；汇总统计不再无条件关联全部履约与 CDK 记录。
- 增加退款状态/创建时间、退款差异检查时间、待核退款差异时间和业务工单列表索引。
- 扩展 `npm run bench:pagination`：由原来的工单、开票、核算、钱包、审计 5 类，扩大到 12 类，新增订单、提现、退款差异、运营任务、两类退款队列和运营首页。
- 基准会拦截 `listOperations`、`listOrdersInternal`、`listWorkspaceRecords`。核心请求若退回全历史扫描，基准直接失败。

## 本地 SQLite 文件基准

测试日期：2026-10-01。每页 20 条，同时发起 40 个后台只读请求。

| 每类记录数 | 并发请求 | 数据库查询数 | P95 | 最大响应体 | 全历史扫描 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 100 | 40 | 73 | 97.98ms | 17,251 bytes | 0 |
| 1,000 | 40 | 73 | 244.21ms | 17,253 bytes | 0 |
| 5,000 | 40 | 73 | 464.55ms | 17,254 bytes | 0 |

验收阈值为 P95 小于 500ms，三档均通过。5,000 档中，订单聚合单次数据库查询 P95 约 53.71ms；退款队列 P95 约 1.93ms；退款差异 P95 约 1.16ms。

## 结果边界

- 这是本机、单 API 进程、SQLite WAL 文件的接口级基准，不等同于生产公网端到端延迟。
- 基准覆盖读并发和响应体边界，不模拟支付宝或上游网络调用，也不写生产数据库。
- 正式发布前仍需使用脱敏生产数据库副本执行迁移演练，并在候选环境复测 API、Worker 心跳和页面操作。
- 退款待审接口新增 `page`、`limit`，旧调用不传参数时仍返回第一页 20 条；现有接口地址和数据字段保持兼容，同时增加 `meta` 分页信息。
