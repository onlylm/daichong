# 合作工作台与双钱包

本轮业务决定覆盖旧文档“代理只能推广、不能自收款”的限制。只开放充值/Quefa CDK，不提供开卡及相关管理。本版仍为隔离联调构建，不代表生产验收完成。

## 入口与账号

访问 `/workspace`，按账号角色显示下单、订单、工单、等级、钱包、公告与账号管理。网页采购与签名 API 复用订单服务。消费者仍使用充值/兑换页面，未开放公众零售账号注册。

首次管理员用 `npm run account:bootstrap -- <账号名>` 初始化；初始密码从临时环境变量 `QUEFA_BOOTSTRAP_PASSWORD` 读取，不放命令参数、源码或聊天。必须用 SQLite；已有管理员时拒绝重复初始化。其他账号首次登录强制改密。

工作台 API 见 `src/operations/routes.ts`，需会话 Cookie，写操作还需正确 Origin 与 CSRF token。账号停用、改角色和改密码使原会话失效。最后一名管理员不能停用/降权。未实现公开注册、自动密码找回或 MFA，生产前需补管理账号强认证、恢复及告警。

| 角色 | 主要权限 |
|---|---|
| 平台管理员 | 账号、等级及销售模式配置、等级审批、全部运营权限 |
| 平台客服 | 工单、内部备注、公告、代理查看；不能改等级或审核资金 |
| 平台财务 | 资金审核、代理和工单查看；不能分配角色 |
| 平台审计 | 账号、工单、钱包、代理只读 |
| 代理主账号 | 本代理下单、工单、等级申请、钱包、创建员工/财务 |
| 代理员工 | 本代理订单、工单、公告和等级查看 |
| 代理财务 | 本代理钱包查询和充值申请，不可提现 |
| 代理 API | 本代理订单业务、工单、等级申请、公告、钱包查询，不可审批资金 |

## 工单、等级与公告

工单支持本代理订单关联、回复、内部备注、状态和已读；内部备注、内部处理人及内部版本变化不对代理显示。暂无附件及邮件/短信通知。

等级申请是结构化工单：目标等级、原因、提交时规则/等级版本、审批状态、审核说明。主账号/API 可申请，每代理最多一份待审核申请，同申请号幂等。管理员通过时在同一事务内更新等级、写审核记录与对外回复，并解决工单。客服不能靠结单替代审核；已审核申请不可反向改判。

申请后规则/代理配置变化则拒绝旧审批，需驳回后重新申请，避免覆盖较新配置。后台也可手工调整等级，均审计留痕。

等级规则按有效供货金额或完成订单数给建议，默认人工审核，不自动升级。统计排除模拟履约、受控联调、未付、普通退款订单；仅签发未兑换的 CDK 不算。建议不是自动获批资格。

等级、账号角色、商品价格、收款方式、自建兑换开关相互独立，升级不自动改价/开权限，不回改历史订单。

公告支持草稿/发布/撤下、定时生效结束、置顶、全部/指定代理/指定等级可见，以及每账号已读。修改版本再次显示未读。纯文本显示，常见密钥与已知供应品牌拦截不是完整 DLP，对外文字仍须审核。

## 双收款模式

### API 开通前置条件（2026-09-27 确认）

主账号先完成采购充值，由平台核实实际到账；申请和审批时均须有已入账充值流水且采购余额大于零。仅提交充值申请、只有收益转入余额、已有 API 密钥，均不替代门槛。暂无额外最低充值金额。

工作台“API 接入”提交申请，平台在工单审核，通过后主账号可创建密钥，秘密只显示一次。遗失先停用旧应用再新建。平台可整体停用 API，代理可停用自己的应用。

所有签名接口检查开通状态，旧演示/预发密钥也不例外。升级后须补齐审核，不能靠重启自动开通。

按用户确认保留两模式：余额采购按供货价扣款，不得超过可用采购余额；平台代收不再扣采购余额。API 开通后不因余额正常消费至零而关闭：仍可查单/查充值结果及创建平台代收订单。已付订单提交履约、CDK 兑换不重复扣供货价，采购扣款发生在下单时。

平台主动停用 API 会阻止全部签名调用，与正常余额用完不同；恢复需新申请审核，回放旧批准不能恢复。

- `platform_collect`：客户付平台，平台核实零售款；履约后财务释放代理收益。
- `agent_collect`：客户付代理，代理自行核实；Quefa 下单事务扣采购余额供货价，不产生第二笔分销收益。

代理支付密钥不交 Quefa，代理声称“客户已付款”不能给钱包加钱。代理自行实现其支付接入。本平台内部收益核算不是支付宝原生分账产品。

## 钱包规则

采购可用、收益可用、提现冻结、待核对收益、收益欠额分别展示。金额用整数分，资金流水仅追加。

采购充值：申请→平台核实实际到账唯一流水→入账。未核实不入账，同一真实流水不能跨代理重复记账；当前没有自动支付宝钱包充值回调。

采购：只扣供货价；余额不足整体回滚，并发不能透支。未履约且无有效 CDK 可由财务退采购余额，不等于已向消费者退零售款。

分销收益：真实履约、非测试、无争议且未进入旧结算后人工释放；与旧结算互斥。可转采购余额，不支持反向任意转出。

提现：先冻结→财务审核→另一名财务/管理员确认线下实际打款流水；不自动转账。需在受控流程核实收款人及账号，本版未存储/自动验证银行或支付宝收款账户。

退款冲减已释放收益，不足显式记欠额并限制采购和提现；已释放收益订单有待确认退款时，暂停新划转/提现及打款确认，仍可驳回提现解冻。真实零售退款通道未接通，线下渠道退款也尚不自动对账。

## 界面设计

使用 frontend-design 指引，以交易任务为主，不放装饰性运营数字。

- 颜色：主蓝 `#114ca4`，正文 `#192c42`，次要文字 `#5b6e82`，底色 `#ecf2f8`，边线 `#dbe5ef`，风险 `#a3481d`。
- Segoe UI / Microsoft YaHei；正文 15px、标题 28px、金额等宽数字、左对齐。
- 218px 左导航，当前代理上下文，任务表单与记录列表；手机导航横向滚动、表单单列。
- 审视后用一条分列资金区代替装饰卡片，明确五种金额性质，风险操作需显式点击确认。

```text
导航 │ 当前账号 / 代理选择 / 刷新
     │ 标题与业务说明
     │ 操作表单
     │ 记录、状态和下一步
```

## 部署边界

账号、工单、钱包、等级、公告使用 SQLite WAL 持久化；memory 仅测试。当前单服务器低订单量允许 `NODE_ENV=production`，必须同时使用独立持久化文件、HTTPS、可信反向代理、MFA 管理域名和非默认密钥。扩展多节点前迁移 PostgreSQL。

服务器已可按生产运行形态部署。真实供应和支付仍须分别配置、只读验证和显式启用；扩大流量前继续完成退款对账、固定出口网络、KMS、网关限流与防爆破、外部告警、压测和异机备份恢复演练。部署本身不得发起充值或付款。

代理外发文档仅选第 16 份和必要签名示例；不要打包内部供应文档、配置或数据库。

安全参考：[密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。
