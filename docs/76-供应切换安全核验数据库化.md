# 供应切换安全核验数据库化

日期：2026-10-01  
状态：本地重构分支已完成并通过自动化测试，尚未部署生产。

## 改造原因

管理员更换上游地址、环境或 API Key 前，系统必须确认不存在未完成订单或仍有效的上游 CDK。旧实现会读取并解码平台全部历史订单，再逐笔查询兑换码和履约记录。历史增长后，一次供应配置保存可能长时间占用同步 SQLite 查询，并阻塞其他后台请求。

## 当前实现

SQLite 仓储新增精确存在性查询，只要发现以下任一情况即拒绝切换：

- 尚未过期的待支付订单；
- 已支付或部分退款、但没有任何成功履约记录的订单；
- 状态为签发中、未使用、已预留或停用中的 CDK。

查询使用订单状态索引和订单关联索引，并以 `LIMIT 1` 结束；不会读取或解码全量订单。内存测试仓储仍保留原有兼容逻辑，两种实现采用相同业务口径。此优化没有放宽供应切换限制，也没有按“最近若干条”截断安全核验。

## 验证

SQLite 回归测试验证：

- 存在未过期订单时切换被拒绝；
- 同一订单过期后不再误阻塞切换；
- 整个过程未调用全量 `listOrdersInternal()`；
- 原有供应地址、密钥、并发配置版本与商品映射测试继续通过。
