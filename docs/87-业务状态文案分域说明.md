# 业务状态文案分域说明

## 修复背景

后台曾共用一张状态翻译表，导致相同状态值在不同业务中被错误解释。例如订单支付的 `paid` 显示成“已登记打款”，退款的 `processing` 显示成“开票中”。

## 当前规则

- 支付：`paid` 显示“已支付”，`pending` 显示“待支付”。
- 退款：`processing` 显示“退款处理中”，`succeeded` 显示“退款成功”。
- 履约：`running` 显示“充值处理中”，`succeeded` 显示“充值成功”。
- 开票：`processing` 显示“开票处理中”，`awaiting_payment` 显示“待付补差”。
- 核算：`paid` 显示“已登记打款”，`pending_payment` 显示“待人工打款”。
- 提现：`approved` 显示“待打款”，`paid` 显示“已打款”。
- 钱包充值：`requested` 显示“待支付”，`credited` 显示“已入账”。

订单列表、订单详情、首页待办、开票记录、代理详情、资金流水和每日核算均调用对应业务的状态映射。通用翻译只作为无歧义状态和未知兼容值的后备，不再决定上述业务状态。

## 回归要求

新增前端脚本回归用例，直接执行各业务状态映射，并检查实际页面组件使用对应的专用标签函数，避免后续把业务状态重新合并到共享映射。
