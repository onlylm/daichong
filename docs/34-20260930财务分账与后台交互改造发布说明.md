# 财务分账与后台交互改造

日期：2026-09-30。版本：`audit-fixes-20260930-finance-ui-v1`。发布状态：北京时间 18:56 已部署生产，API/Worker 同版且健康检查通过。

本轮按现有蓝色运营后台进行实质交互调整，不更换前端框架，不修改历史售价、余额、退款或分佣记录。服务器连接继续使用已有部署账号和本机密钥；本文件不包含登录密码、业务密钥或充值凭据。

## 1. 充值进度反馈

订单列表及打开的订单详情，在有未完成付款、充值或发码任务时约每 3 秒读取一次。每个轮询只保留一个在途请求；隐藏页面暂停，嵌套编辑弹窗暂停详情刷新，异常逐步退避到 30 秒。终态后停止轮询。列表只更新行与汇总；详情无状态变化不重建，变化时保留展开区域与滚动位置。

详情不再把 queued/running 标成“履约已完成”，按统一阶段显示排队、登录、资金准备、充值、结果核对等已确认进度及最后变化时间。公开失败原因和最新尝试的恢复规则不变：仅明确失败且允许重提时开放原订单输入入口；结果未知不能取消或重复下单。代理直接在后台下单和 Partner API 下单共用同一套业务任务状态。

这不是 WebSocket/SSE 或逐秒推送。上游正常任务约 5 秒核对一次，网络异常约 15 秒后重查；总体延迟还受上游更新和队列数量影响。API 查询与持久化的 `fulfillment.updated` 通知均已支持，代理商实施规则见公开文档 7.4–7.5 节。

## 2. 页面响应与数据库读取

实时 GET 不再清空所有配置与页面缓存；同账号、租户、方法和路径的在途读取合并，单个页面取消不会中止其他读取者。写请求仍使缓存失效，并阻止写入前的迟到结果重新填入缓存。余额、订单、退款、敏感凭据不使用陈旧结果作操作依据。

财务子页按当前标签取数；支付通道配置与验证/启用放在专用原生弹窗。配置草稿、验证、启用仍为三个独立步骤；关闭弹窗清空输入的密钥，不回显保存值。确认与说明输入改为可取消弹窗，保留执行中的按钮状态、错误和焦点返回。

订单详情首屏只取普通详情；上游兑换码由管理员显式按需读取，继续记录审计且禁止缓存。代理无法获得上游原始码或成本交易凭证。

SQLite 列表批量读取当前租户范围的订单、履约与兑换码；单笔履约和兑换码关联使用 JSON 表达式索引。当前筛选、排序和分页仍在内存完成，尚未完成全量 SQL 分页或 PostgreSQL 迁移。不能据此保证大数据量时永远秒开。

本轮早期只读样本：20 个商户、97 笔订单，平台第一页 20 行读取 157 次 SQL，单次冷调用约 477ms。发布前后再次使用同一只读诊断脚本、同样 20 个商户/102 笔订单：旧版三次 402.81–458.27ms、每次 162 次 SQL；新版三次 15.78–24.08ms、每次 1 次 SQL。新增复用的上海时区日期格式器也避免逐单重复实例化。

采样不启动业务 Runtime，不解密凭据，不执行资金变更，使用只读 SQLite 快照。读取权限配置使用固定空可见性回调，未计入实际 HTTP 路由、账号鉴权、代理配置、网络或浏览器开销；不代表并发性能、浏览器耗时或 P95。

## 3. 分佣、成本、补差三者分开

订单详情分别显示代理分佣/采购、美元成本核算、客户补差及付款凭证。资金管理新增“成本与补差”待办，最多列出最近 200 笔已履约或已有核算记录的订单；不是完整历史导出或日结单。

分佣仍使用订单冻结供货价与既有零售退款规则。成本变化与成本节省补差不红冲分佣、不调整冻结售价、不记为代理新增利润。平台代收和代理自收采购的原有账本不改动。

商品设置可配置标准美元扣款、人民币内部成本及保留费用（默认 0.15 USD）。新订单冻结成本口径和商品版本，兼容旧商品别名；修改商品不回填历史订单。历史缺失快照须管理员核实下单口径，不能猜测使用今天的成本。

核算公式：毛节省 = max(标准美元成本 − 实际美元成本, 0)；净补差 = max(毛节省 − 保留费用, 0)。独立额外费用有独立字段，不能把保留费用又计入实际成本。超扣进入争议，不产生负补差，也不减佣金。

有真实汇率时按整数货币单位计算人民币成本和毛利。标准与实际美元相等且无额外费用时，可使用已冻结的人民币内部成本；没有真实汇率/成本凭证则保留待核算，不杜撰利润。成本确认不等于已支付。

## 4. 按上游订单核对美元交易

查询链路为平台订单 → 最新关联履约 → 上游订单号 → 该单实际卡片 → USD 交易。订单详情按钮“按上游订单查美元成本”只发起上游 GET，不充值、不删卡、不转账。

优先使用交易的明确订单号。没有该字段时，要求订单的实际卡片、原币最终金额/币种、创建至完成的限定区间共同匹配，并只接受唯一交易标识；不选最近一笔，不因同金额就强行关联，同卡多笔匹配或凭证已用于其他单时保留待核验。

只读取正金额、USD、COMPLETE 且属于 OpenAI 的 Authorization/Settlement 记录。明确 Settlement 标为清算候选；Authorization/COMPLETE 只是授权记录投影，不等于已证明清算。金额候选预填表单，但本版仍须管理员确认真实关联和清算证据后核算，不自动确认成本或出款。上游卡注资、删卡返还、账户余额日志不能代替逐单消费成本。

新订单履约成功后，Worker 以独立只读任务自动读取候选，单条约每 15 分钟再核对，仅扫描近期新订单；不批量迁移历史核算，不阻塞充值任务。历史单可由管理员点击读取。

## 5. 补差处理与防重复

核实成本时选“直接退最终客户”或“退代理，由代理代退客户”。管理员只登记已实际完成的付款、唯一流水、真实金额/币种及证据；系统不自动退款或转账。付款后禁止覆盖成本、切换去向、重复使用凭证或超额核销。代退全额支付后，另确认客户实际收到，不能把代理到账当成客户完成。

旧差价退款与新成本补差路径互斥：已有旧退款不能再重复核销，已确认新核算不能另建旧差价退款，已登记新补差付款后不能再直接普通退款或采购退款。需要进一步处理时人工核对与争议解决，不覆盖原记录。

本轮没有完整的 22 点补差日结单、财务导出、付款凭证冲正或 Partner API 补差回执；既有分佣结算任务继续运行。不能声称另一单商户文档中的全部功能已实现。
