# 恢复演练摘要权限边界

## 文件分层

- 完整恢复报告：保存在备份快照旁，root 属主，权限 `0600`。包含内部校验细节，不提供给应用容器。
- 健康摘要：`/opt/recharge-platform/monitoring/sqlite-restore-health.json`，仅包含状态、验证时间、传输页数、完整性结果、记录数和两个一致性摘要。

## 属主和挂载

脚本以 `production.sqlite`（首次切换前兼容 `prelaunch.sqlite`）作为属主参考：

- `/opt/recharge-platform/monitoring`：同数据库属主，`0750`。
- 脱敏摘要：同数据库属主，`0640`。
- 容器挂载：`/opt/recharge-platform/monitoring:/app/health:ro`。
- 应用读取：`BACKUP_HEALTH_REPORT_PATH=/app/health/sqlite-restore-health.json`。

这样 API 的非 root 进程可以只读健康摘要，但不能读取完整报告、备份快照或扩大生产账本权限。成功与失败摘要都使用同目录临时文件加原子 `mv` 发布，避免 API 读到半写内容。
