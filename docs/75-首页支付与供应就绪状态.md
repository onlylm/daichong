# 首页支付与供应就绪状态

日期：2026-10-01  
范围：平台管理员首页运营状态栏

## 改造结果

平台首页不再把“支付通道”和“上游供应”永久显示为“未检测”。

- 支付通道读取当前服务实际可用的支付宝配置，显示“支付宝已启用”或“支付宝未启用”。
- 上游供应读取生产供应连接的启用状态、最近一次连通测试结果和套餐同步时间，分别显示未启用、待验证、最近验证失败、套餐待同步或已验证。
- 支付和供应状态卡可直接进入对应配置页面处理。
- 数据备份读取隔离恢复演练发布的受保护结果：成功且未过期才显示“备份恢复已验证”；失败、报告无效和超期分别明确显示；从未执行时仍显示“未检测”。

## 状态边界

首页展示的是本地持久化的配置与最近一次验证结果，不是对支付宝或上游接口的实时探测。打开首页不会调用外部接口，也不会产生外部副作用或额外延迟。管理员需要最新外部结果时，应进入“支付设置”或“生产供应”执行原有验证动作。

备份状态也不以“定时器存在”或“快照文件存在”代替恢复成功。后台仅读取恢复服务原子发布的摘要文件，默认有效期 192 小时；摘要缺失、损坏、结构不完整、时间异常或恢复命令失败都不会被标记为健康。

支付与供应状态包含 `scope=configuration`，备份状态包含 `scope=restore_rehearsal`，分别表示配置就绪性和真实隔离恢复证据。任何读取失败均独立标记模块不可用，首页保留其他模块的旧值并提示数据已过期，不能把缺失数据显示为正常或零。

## 验证

- 覆盖支付未启用、供应未启用及备份未检测的默认状态。
- 覆盖支付宝已启用、供应最近验证成功且套餐已同步的就绪状态。
- 覆盖恢复报告缺失、成功、过期、失败、损坏、伪造成功结构和未来时间。
- 工作台静态检查覆盖状态文案读取和支付／供应配置入口。
- 首页状态读取不发起支付宝或上游网络请求。
