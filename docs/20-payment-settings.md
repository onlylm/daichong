# 后台支付配置：支付宝与 USDT

## 交付状态

2026-09-27：已按用户授权实现双通道后台配置、建单、到账校验及履约衔接，并支持生产执行模式。部署不会自动读取或生成真实凭据，也不会自动创建付款；新部署的两个通道均保持关闭，必须由平台管理员逐项保存、验证并启用。

## 一次性部署准备

1. 使用独立 HTTPS 域名、独立 SQLite 数据库和服务账号；API 与 Worker 共享数据库和加密主密钥。
2. 正式运行设置 `NODE_ENV=production`、`EXECUTION_MODE=production`、`PAYMENT_PROVIDER=managed`、`FULFILLMENT_PROVIDER=zovocard`、`ENABLE_SANDBOX_ROUTES=false`、`LIVE_TEST_ENABLED=false`。若只做限额白名单联调，改用 `EXECUTION_MODE=controlled` 并配置第 14 份文档的白名单和限额。
3. 更换 DATA_ENCRYPTION_KEY（随机 32 字节 Base64）以及平台管理令牌、会话/页面令牌秘密、代理 API 秘密。主密钥不能放进数据库备份中，必须另行安全备份；丢失主密钥会无法解密旧单凭据。
4. `controlled` 模式配置专用代理白名单及单笔、累计金额和笔数上限；`production` 模式不使用联调额度，依靠全局执行模式、支付通道状态、代理权限和商品状态控制业务。
5. 启动 API 和 Worker，初始化平台管理员；管理页放在 VPN/IP 访问控制后，回调路径需公网可达。
6. 新库的两个通道均关闭。支付凭据随后由管理员在 /workspace → 支付设置填写，无需发送给开发人员。

生产部署使用 `compose.production.app.yaml` 与 `/opt/recharge-platform/config/production.env`；受控联调仍可沿用 `compose.live-test.yaml`，不得和模拟 compose 混用。
从原支付宝文件模式迁移时，若数据库已有未绑定配置版本的旧订单，必须保留原 ALIPAY_* 参数和文件，直到旧订单核对、售后完成；缺失旧文件时启动会失败，不能丢弃旧单凭据。

## 后台使用

支付设置仅平台管理员可访问；代理、客服、财务、审计账号不能读取或修改。

1. 填写并“保存草稿”。密钥加密持久化，不回显；留空保留已有密钥。切换应用、项目或 API Key ID 时必须重新填入相应密钥。保存草稿不会替换当前启用版本。
2. 点击验证。支付宝验证 RSA 格式与长度，不能证明产品权限或真实到账；USDT 仅只读校验商户、项目、Key ID 三者一致。验证结果 30 分钟内可用于启用。
3. 配置服务商回调地址，确认后点击“启用此配置收款”。此操作允许后续真实付款与对应履约，不只是修改显示状态。
4. 可关闭支付宝、关闭 USDT，或“关闭全部收款通道”。批量关闭在一个事务内完成，过期页面版本会被拒绝，须刷新。

关闭后的语义：

- 不允许该通道创建新销售订单或为尚未发起付款的旧订单发起付款。
- 已发起的支付宝页面、已展示的链上地址不能保证立即失效，也不是退款。已有付款仍验签、查单和履约。
- 已提交的 USDT 建单意图发生网络超时后，会用原幂等键恢复，不因开关变化换一张支付单。
- 到期且建单结果未知时停止自动重新建单，列入待核对；收到有效原订单回调后仍可恢复服务端核验。
- 全部关闭不影响代理余额采购，不退回已经扣除的采购金额。

## 支付宝

填写 APPID、收款商户 PID、PKCS8/PKCS1、应用私钥及支付宝公钥。
界面密钥框可填去掉 PEM 头尾的 Base64；不要把应用公钥误填为支付宝公钥。
固定使用官方电脑网站支付网关和 RSA2，不接受后台填写任意网关地址。

每笔订单绑定下单时的配置版本。通知核对签名、APPID、PID、订单、金额、交易号；浏览器跳转参数不作为到账依据。关闭通道或保存新草稿不会关闭旧单通知与查单。

## USDT / DujiaoPay

填写商户 ID、项目 ID、API Key ID（不是 Key Prefix）、API Secret、Webhook Secret，并明确选择收款网络。
首版支持选择 TRON、Ethereum、BSC 或 Solana 上的 USDT；一个启用版本固定一个网络，实际需在服务商后台启用相应收款地址、币种及套餐权限。没有默认替用户选择网络。
收款钱包地址在服务商后台配置；本平台不收集钱包私钥或助记词。

保存后复制页面生成的回调 URL 到对应项目。回调 URL 带配置版本，轮换时更新服务商配置；同商户同项目的新回调密钥可通知旧订单，但旧订单查单仍绑定原 API 凭据。不要提前撤销旧 API 密钥。

建单币种为 CNY、金额为十进制字符串，服务商锁定汇率与精确 USDT 数量。人民币订单金额和 USDT 到账证据分别保存，不把 USDT 数量写成人民币分。
收银台展示网络、地址、精确数量和截止时间，可复制地址/数量；不跳服务商收银台，不向客户提供充值供应商信息。首版未生成扫码二维码。

自动确认付款要求同时满足：

- 回调签名、时间窗、事件 ID 与原始请求字节匹配；持久化去重，同 ID 不同内容拒绝。回调本身不直接置为已付。
- 后台主动查单，订单号、法币、金额、链、币种、地址、应付数量与原订单绑定一致。
- paid_source=chain，链上确认数满足当前适配器门槛，实收等于精确应付额，交易哈希不曾支付其他订单，到账时间与汇率证据有效。
- 人工认领/人工标记、金额不符、网络不符、确认数不足、逾期到账等进入待核对，不触发发码。不提供人工强制置为已付按钮。

Worker 每笔最多约每 60 秒查单；页面每 5 秒查询本平台缓存状态。回调和定时查单共同补偿漏通知；查询限频与任务占用持久化，API 与 Worker 可并发运行。

官方规范：[DujiaoPay 接入文档](https://www.dujiaopay.com/docs)。身份检查通过不等于已经验证 CNY 支持、收款地址、报价、套餐权限或真实到账；这些须部署后做一笔受控联调。

## 履约与财务边界

平台代收订单付款成功后沿用原 order.paid、台账和下游通知；不再扣采购余额。
CDK 订单由 Worker 签发上游码并映射为 QF 码，发码本身可能向上游产生费用。
直充或 CDK 兑换仍需客户提交资料；`controlled` 联调订单继续逐笔批准，`production` 订单在真实付款核验通过且生产上游已启用后由 Worker 自动履约。
联调订单不计正式等级业绩、不释放正式收益。生产订单的 USDT 渠道识别已衔接等级与收益规则，不改变财务人工核对要求。

真实退款和完整渠道手续费自动对账尚未交付。服务商 refund_recorded 只表示记录，不是转账退款；本次不调用钱包转账，不把退款登记自动记为成功。模拟退款入口拒绝真实支付订单。

## 新增接口

工作台接口共用账号会话、同源检查和 CSRF：

- GET/PUT /workspace/api/payment-settings：脱敏状态、保存草稿。
- POST /workspace/api/payment-settings/check：{channel, version}。
- POST /workspace/api/payment-settings/enable：另须 confirmRealPayments=true、confirmCallbackConfigured=true。
- POST /workspace/api/payment-settings/disable：{channels:[{channel,version}]}，可一项或两项。
- GET /workspace/api/payment-reviews：USDT 待核对列表。

以上后台 channel 为 alipay_page / dujiaopay，只供平台管理员使用。代理接口仅暴露 alipay / usdt，见第 21 份指南。
