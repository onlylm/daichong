# 每日核算退款范围与打款幂等修复

## 修复范围

### 1. 退款保护限定到本核算单

确认每日核算单打款前，系统仍会检查关联订单是否存在待确认退款。但 SQLite 原实现按代理商全部已释放收益订单检查，导致某个不属于当前核算单的订单进入退款流程时，也会阻止当前核算单登记打款。

现改为：

- 每日核算单仅检查自身 `orderIds` 对应的待确认退款；
- 关联订单存在 `requested / approved / processing` 退款时继续阻断；
- 同代理商其他订单的退款不会误伤当前核算单；
- 钱包划转和提现仍使用代理商全量保护，不缩小原有资金安全范围。

SQLite 查询按最多 400 个订单号分批执行，避免参数数量超限；空核算单直接返回无待退款。

### 2. 打款登记使用完整内容幂等

核算单已经登记为 `paid` 后，只有以下字段全部与原记录一致时才作为安全重放返回：

- 付款流水号；
- 付款方式；
- 付款凭证说明；
- 内部备注。

相同流水号但内容不同不再静默成功，而是返回 `daily_settlement_payment_conflict`。这可以防止操作人员误以为后一次提交已经修改了历史付款凭证。既有钱包扣减分录仍使用 `settlement_payout:{statementId}` 唯一标识，重复请求不会重复扣款。

## 回归覆盖

- 当前核算单关联订单存在待退款时拒绝登记打款；
- 待退款取消后允许登记；
- 同一代理商无关订单存在待退款时不阻断本单；
- 完整相同的打款登记可安全重放；
- 相同流水号但方式或凭证不同会明确冲突；
- SQLite 候选、余额和退款检查保持数据库侧执行，不回退全历史扫描。
