# 开票补差重复到账核对

## 规则

同一开票申请可以因支付意图过期而生成新的补差价支付单，但只能有一笔到账成为申请的正式付款关联。

## 到账处理

1. 首笔经支付宝验证成功的支付单成为正式付款，开票申请进入已提交。
2. 同申请的其他待支付意图立即本地关闭，停止继续展示为可付款。
3. 若已关闭或已过期的另一支付意图随后被支付宝确认实际到账，系统保留该支付单和支付宝流水。
4. 第二笔到账建立独立的 `invoice_payment_reconciliation` 财务核对记录，状态为待核对。
5. 开票申请始终保留首笔付款 ID 与首笔支付宝流水，第二笔不得覆盖。

支付宝明确返回 `TRADE_CLOSED` 的支付单仍保持终态，不能凭本地请求直接改记为到账。只有同申请因另一笔先到账而本地关闭的支付意图，之后收到已验签的成功事实时，才进入重复到账核对。

## 追溯

重复到账核对记录同时保存正式支付单、重复支付单、两笔支付宝流水和金额。该记录属于财务差异，不使用售后工单承载。

## 后台处理入口

- 平台首页“补差重复到账”独立待办显示全量待核对数量及最早记录；点击具体记录进入双流水核对详情。“查看全部”进入发票管理的重复到账分页列表，代理商管理详情的开票页也可查看当前代理的记录。
- 仅平台有开票管理权限的账号可读取两笔支付宝流水；仅平台管理员可登记“重复款已退”。代理商不会看到内部重复到账核对记录。
- 管理员须先在支付宝完成重复款退款并核实真实退款流水，再填写退款流水号和凭证说明。此登记动作**不调用支付宝退款接口、不修改客户订单、代理钱包、佣金或每日核算单**；退款实际执行仍在平台外部人工完成。
- 登记在事务内复查申请与两笔支付关联、版本及退款流水唯一性；相同内容重试幂等，不同内容或过期版本拒绝。原始两笔支付和审计记录继续保留追溯，待核对队列只移除已登记退款的记录。

当前改动仅在开发分支验证，尚未部署生产；页面实际操作与支付宝外部退款仍待管理员验收。
