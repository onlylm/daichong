# Webhook 投递有界领取

日期：2026-10-01（北京时间）  
状态：本地重构分支已完成并通过自动化测试，尚未部署生产。

## 问题

Webhook Worker 每秒运行一次。原 SQLite 实现会读取并解码全部历史投递记录，再在内存中筛选待投递或租约超时的任务，最后只领取前几笔。随着已成功投递历史增长，即使当前没有任务，也会反复扫描全部记录。

## 当前实现

- 在同一个 `BEGIN IMMEDIATE` 事务内，只查询状态为 `pending` 且已到重试时间，或状态为 `delivering` 且租约已过期的记录。
- SQL 内完成到期判断、排序和 `LIMIT`，Worker 每轮仍最多领取调用方指定的数量（当前 5 笔）。
- 新增状态与租约时间索引；待重试任务继续使用既有状态/下次尝试时间索引。
- 领取后仍在同一事务写入 `delivering`、租约时间和尝试次数，再读取对应端点和 Outbox 事件。

## 不变的安全与交付规则

- 不改变 Webhook 正文、签名头、事件编号和订阅规则。
- 多 Worker 仍通过写事务串行领取，不能同时领取同一投递。
- HTTP 非成功、网络超时继续按原退避表重试；达到上限进入死信，不伪造成功。
- 已成功或已死信的历史记录不会重新进入候选。

## 验证

SQLite 回归一次创建 10 笔到期投递，确认只领取 3 笔，并确认候选 SQL 自身包含状态、租约与 `LIMIT`；现有签名和投递回归继续通过。

最终结果以 `npm run check` 为准。本轮不部署生产，也不向真实代理端点发送 Webhook。
