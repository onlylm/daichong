# 充值与成本 Worker 有界队列

日期：2026-10-01（北京时间）  
状态：本地重构分支已完成并通过自动化测试，尚未部署生产。

## 问题

CDK 签发、退款后的停码、退款后的未派发任务关闭、充值履约和成本回读都属于高频后台任务。原实现会先读取完整历史订单或整类记录，再在 Node.js 中寻找一笔候选；历史增长后，即使没有任务可处理，也会持续消耗 SQLite 读取、JSON 解码和事件循环时间。

## 当前实现

- CDK 签发每轮最多读取 20 笔已付款、未退款、尚未签发或已到重试时间的候选订单。
- 退款停码只读取一笔已退款且仍有可停用上游 CDK 的订单；已成功或结果未知的充值任务会阻止停码。
- 退款履约清理只读取一笔仍有未派发任务、待写入退款恢复动作或残留充值入口的订单。
- 普通履约每轮最多读取 20 笔到期候选；SQLite 在查询阶段排除未经逐笔批准的受控实单任务。
- 成本回读只读取一笔 48 小时内、履约成功、有冻结成本基准、尚未确认且已到核对时间的订单。
- CDK 释放和消费改为按兑换凭证主键精确读取，不再为了一个凭证遍历全部兑换码。

内存仓储仍保留原行为作为隔离测试回退；生产 SQLite 使用有界 SQL 候选查询。查询不到候选即结束本轮，不会从完整历史记录中继续近似选择。

## 安全边界

- 本轮只改变候选读取方式，不改变支付确认、CDK 加密、兑换状态机、充值租约、退款状态或成本人工确认规则。
- 退款后只取消从未提交到上游的任务；存在上游订单号、查询令牌或结果未知时不会当作未派发任务关闭。
- 上游 CDK 只有在订单已退款、兑换码仍可停用且全部充值尝试都明确失败或取消时才进入停码。
- 成本自动回读仍然只读取上游事实，不会自动确认成本、自动退款、自动补差或变更代理余额。
- 受控实单的逐笔批准仍是持久化安全条件，缩短查询列表不能绕过。

## 代理充值时间追溯

代理资金页的充值记录新增“发起时间”和“到账时间”：

- 发起时间取充值申请的 `createdAt`；
- 支付宝在线充值以验签或官方查询确认入账时写入的 `paidAt` 为到账时间；
- 人工核实充值在批准时同步写入 `paidAt`；
- 旧的已入账数据若没有 `paidAt`，界面用最终处理时间兼容展示；未到账记录显示为空。

这两列用于对应支付宝流水、判断到账延迟和追溯人工处理，不以浏览器返回页时间代替服务端确认时间。

## 自动化验证

新增 SQLite 回归覆盖：

- 22 笔待签发订单只返回 20 笔候选，并确认签发服务不调用订单全量读取；
- 已退款且未兑换的 CDK 能被精确命中和停用，不扫描历史订单；
- 已退款、从未派发的充值任务能被精确关闭并撤销充值入口；
- 只有履约成功且尚未确认的订单会进入成本回读，人工确认后立即退出候选；
- 按 CDK 主键能精确读取；
- 人工核实充值会持久化到账时间。

最终结果以 `npm run check` 为准。本轮不部署生产，也不调用真实支付宝或上游充值服务。
