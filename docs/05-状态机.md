# 状态机定义

版本：v0.2。所有转换必须在事务中同时写业务表、`state_transitions` 和必要的 Outbox/财务分录。`merchant_id` 在本文中表示代理商租户；所有支付状态均由 Quefa 自有支付宝通道的可信结果驱动。

## 支付

```text
pending ──Quefa支付宝确认──> paid
   ├──到期──> expired
   └──关闭──> closed
paid ──部分/补差退款成功──> partially_refunded
paid/partially_refunded ──可退金额归零──> refunded
```

禁止：`expired/closed → paid` 的本地直接修改。若 Quefa 支付渠道显示迟到付款，进入对账异常，由支付查询和人工流程处理。到账必须同时校验支付宝通知签名、Quefa 支付应用/收款主体、订单号、金额，并主动查单。代理商页面、付款截图、代理商 API 请求均无权把订单改为已支付。

## 履约

```text
queued ──领取──> running ──结果成功──> succeeded
   │                └──确定失败──> failed
   └──取消(尚未外部提交)──> cancelled
running ──查询未知──> running
```

`running` 表示可能已产生外部副作用，租约超时后只能查询/恢复原任务，不得新建外部请求。终态清理 Session。失败码与面向用户的中文说明分离，未知上游错误映射为 `other`，原始响应加密/限期保留且不对代理商暴露。

沙箱实现已在外部写请求发送前持久化 `running/submission_pending`，并加密保存 CDK 查询令牌。预检失败发生在提交之前时可重试；提交之后网络超时、查询鉴权失败或结果暂时不存在，都保留 `running`，不得释放兑换码或开启第二次充值。直充响应丢失时按原 `client_request_id` 从订单列表补查；每轮最多扫描 10 页，每页 100 条，仍找不到时保留待确认，由人工对账处理，不自动重发。记录已提交但进程在发送前退出的极端情况也会进入这一待确认流程。

任务领取和租约令牌在数据库事务中保存，Worker 写回前校验令牌。Webhook 先完成时，迟到的 HTTP 响应不得覆盖终态。履约终态、CDK 消耗/释放和下游事件在同一事务落库。

## Quefa CDK

```text
issuing ──签发成功──> unused ──客户提交兑换──> reserved
    └──确定失败──> failed
                         ↑                  ├──充值成功──> consumed
                         └────确定失败──────┘
unused ──运营停用──> disabled ──运营恢复──> unused
```

对外只存在 `QF-` 码。底层兑换凭证在 `unused/reserved` 期间加密保存，`consumed` 后立即清除。`reserved` 对应的充值结果未知时只能查询原任务，不得重新兑换；确定失败才释放为 `unused`。

## 退款

```text
requested ──Quefa审核通过──> approved ──Quefa提交支付宝──> processing ──成功──> succeeded
    ├──审核驳回──> rejected                 └──确定失败──> failed
    └──尚未审核撤销──> cancelled
failed ──人工确认可安全重试──> approved
processing ──结果未知──> processing（只查询）
```

申请即对可退金额加锁。审核规则同时检查支付、履约和已有退款。`price_adjustment` 是退款子类型，不改变履约状态。重复退款按 `(merchant_id, merchant_refund_no)` 与渠道请求号防重。代理商只能申请和查询，实际退款只能由 Quefa 使用自有支付宝执行。

当前普通退款会拒绝正在履约、履约已成功或存在签发中/有效 CDK 的订单；申请退款后禁止创建新履约和签发新 CDK，已发生普通退款的订单不能再充值。已发出的有效 CDK 若需退款，必须先完成服务侧失效及资金核对；当前不提供自动停码退款流程。补差退款独立保留。

## Webhook 投递

```text
pending ──领取──> delivering ──2xx──> delivered
   ↑                └──失败且可重试──> pending(next_attempt_at)
   └────────────────租约恢复──────────┘
失败达到上限/永久错误 ──> dead_letter ──人工重放──> pending
```

重放创建新的 `delivery_id`，但引用同一 `event_id`；接收方应按 `event_id` 或 `delivery_id` 去重。URL 变更不修改历史投递。

## 结算

```text
draft ──生成完成──> reviewing ──财务确认/封存──> confirmed
confirmed ──发起付款──> paying ──付款确认──> paid
                               └──确定失败──> failed ──重新付款──> paying
draft/reviewing ──作废──> cancelled
```

`confirmed` 后明细和金额不可变。后续退款生成新账期负向 `settlement_adjustment`，并引用原结算行。禁止把 `paid` 改回草稿或删除。

## 代理商、开放 API 应用与密钥

- 代理商：`onboarding → active → suspended → closed`；暂停时禁止新开单，允许查单/退款/对账。
- 应用：`active → disabled`；禁用立即拒绝签名请求。
- 密钥：`active → expiring → revoked`；新旧双钥仅在轮换窗口并行，`revoked` 不可恢复。

以上应用和密钥只用于代理商调用 Quefa 开放 API，与支付宝应用、证书和私钥无关。支付配置由 Quefa 平台单独管理，不存在代理商侧状态机。

## 转换审计字段

每次转换记录 `aggregate_type/id`、`merchant_id`、旧/新状态、原因码、人工说明、操作者类型与 ID、`request_id`、外部流水摘要和时间。敏感原文不得进入审计日志。
